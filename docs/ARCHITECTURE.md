# 설계 초안

## 구성

시세/계좌 어댑터 → 전략 → 주문 의도 → 위험 검사 → 주문 실행 → 체결·포지션 동기화 → 기록/화면.

Codex와 Claude Code는 개발·검토를 분담한다. 운영 중 두 모델 API를 호출하는 기능은 아직 범위에 확정되지 않았다. 자동 모델 호출을 추가해도 주문 실행 엔진의 한도 검사를 우회할 수 없게 한다.

## 시장별 분리

| 시장 | 연결 대상 | 검증 통화 | 주요 후속 작업 |
|---|---|---|---|
| 국내주식 | KIS 국내주식 | KRW | 거래 시간, 휴장, 가격/수량 단위, 계좌 권한 |
| 미국주식 | KIS 해외주식 | USD | 거래소 코드, 서머타임, 세션, 환율, 해외주식 권한 |
| 선물 | Bybit V5 | USDT(임시) | 계약별 수량 단위, 모드, 마진, 레버리지, 펀딩, 청산 위험 |

단방향 모드는 계약별로 하나의 순포지션을 사용한다. 헤지 모드는 롱과 숏을 구분하므로 포지션 키에 방향을 포함해야 한다. 현재 검증 초안은 단방향만 지원한다.

## 현재 구현과 한계

`trading_lab/core.py`는 주문 의도의 양수/유한 숫자, 통화, 정수 주식 수량, 주문 명목 금액, 포지션 명목 금액, 레버리지, 포지션 감소 방향을 검사한다. 멈춤 상태는 모든 의도를 거절한다. 청산 주문은 기존 포지션을 넘거나 반전시킬 수 없다.

제한 값은 외부에서 주입하며 시장별 통화로 계산한다. 선물 명목 금액은 현재 임시 모델에서 수량×예시 가격이다. 레버리지를 곱하거나 나누어 주문 위험을 축소하지 않는다. 실제 계약 승수와 거래소별 수량 규칙은 어댑터가 추가되어야 한다.

검사 함수는 상태를 수정하지 않는다. 동시 주문, 미체결 예약, 재시작 시 중복 방지, 실제 레버리지 확인, 손익/잔고/증거금/손절/강제청산 계산, 시세 신선도 검사는 아직 없다. 따라서 이 검증 함수를 실거래 위험 엔진으로 사용하면 안 된다.

## 실거래 연결 전에 구현할 기능

영속적인 주문 ID와 상태 전이, 타임아웃 후 주문 조회, 부분 체결, 수수료, 잔고/포지션 복구, 시세 끊김 중단, 일별 손실 한도, 계좌별 누적 노출 및 미체결 예약, 종목 허용 목록, 거래 세션, 거래소 수량/가격 정밀도, 보호 주문 확인을 구현하고 테스트한다.

긴급 정지는 신규 주문 중단, 미체결 취소, 보유 포지션 청산을 서로 구분해야 한다. 현재 `halted` 검사는 오프라인 검사 전체를 중단할 뿐 자동 취소/청산 기능이 아니다.
