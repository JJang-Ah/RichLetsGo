## 병합 전 P2 수정

1. **입력 오류/만료와 권한 거절 분리.** 허용 개인 채팅의 `/start`, 잘못된 `/resolve`, 무효 확인 입력은 안내 응답과 `reason_code=invalid`; 만료 확인은 `expired`로 감사한다. 미등록/그룹은 계속 무응답·`unauthorized`다. 감사의 종결 상태 `rejected`는 유지하며 사유 코드를 별도로 저장한다. 입력 원문/불필요한 인수는 저장하지 않는다.
2. **불필요한 콜백 ID 문자 제한 제거.** nonce의 서버 소유권·요청자/채팅/메시지 바인딩은 유지하고, 조회/응답용 query ID는 불투명 문자열로 받는다. 특수 문자/한글 query ID의 만료 버튼도 callback→expired로 분류하는 합성 테스트를 고정했다. message_id가 미기록이어도 소유한 확인이 만료됐다면 종료하며 무기한 활성 상태로 남기지 않는다.
3. **미확인 평가액의 재개 차단.** EquityTracker의 확인 여부를 명시하고 app 초기값은 `unconfirmed`다. ResumeService는 요청/확인 두 단계 모두 미확인 상태를 숫자 0처럼 판단하지 않고 **평가액 미확인: 재개 불가**로 거절한다. CommandService가 버튼 없이 종결 거절을 반환하므로 웹·Telegram이 같은 경로다. 실제 확인된 0 계좌와는 구분한다.
4. **저장·재시작.** 새 확인 플래그는 기존 JSON payload에 저장해 스키마 변경이 없다. 과거 필드가 없는 완전한 0 초기 상태는 보수적으로 미확인으로 읽고, 기존 양수 기준/최고점 기록은 보존한다. 초기 미확인 상태가 /pause로 저장됐어도 Trader는 정산 후 실제 준비 계좌 스냅샷으로 초기화한다. 준비 전 진입은 차단한다.

기존 pause_revision·record_peak 일치·평가액 허용 폭·확인 일회성·시스템 정지 보존 규칙은 유지한다. 단위 (b) 이후 사용자가 발견한 결함을 합성으로 검증한 것이며, 사용자에게 수동 확인을 다시 수행했다고 주장하지 않는다.
