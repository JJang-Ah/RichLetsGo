# D104 용량 점검 범위와 실행 절차

기준 커밋 234dd53의 M2-11 §4.1을 구현한다. **실행 시점은 Claude의 가드 검토·병합 후**다. 거래대금 하한 변경안 #86이 열려 있는 동안에는 구 기준으로도 수집하지 않는다. 변경안이 채택되면 새 종목·메타데이터 파일·하한·명세 해시를 먼저 가드와 대조해 다시 검토받는다. 도구는 명세 파일의 바이트가 달라지면 첫 요청 전에 중단한다.

## 읽을 수 있는 자료

- 게시된 stock.json의 상장 시각과 D103-sessions.json의 XNYS/XKRX regular 행을 사용한다. 두 파일의 SHA-256을 검사한다. 고정 종목은 MUUSDT, NVDAUSDT, SNDKUSDT, SPCXUSDT, SKHYNIXUSDT다.
- UTC 2026-09-01 00시까지 완전히 끝난 정규 세션마다 직전 완결 UTC 일 30개를 열거한다. 첫날 시작이 상장 전이면 워밍업이다. 필요한 날짜의 합집합만 정렬해 연속일을 최대 30일씩 요청한다.
- 목적지는 api.bybit.com의 공개 GET /v5/market/kline 하나다. linear, interval=D, 심볼, start, end(배타 끝에서 1ms 뺀 값), limit을 고정한다. 리디렉션은 따라가지 않는다. 연결 실패·빈 목록은 같은 페이지를 최대 3회 시도한다. 일부 결측은 입력 오류다. 응답 밖 시각·심볼 오류·충돌 중복 발견 즉시 중단하고 사고 시각과 요청 범위를 남긴다. 응답 원문과 OHLC·수량은 저장하거나 출력하지 않는다.
- 정규화 해시는 심볼·일 시작 오름차순의 JSON 배열 [심볼, UTC ms, 정규 Decimal 거래대금 문자열]을 공백 없이 UTF-8 LF로 이어 SHA-256으로 계산한다. 결과 파일에는 입력 해시, 심볼별 일수·상한·자격 수, 합계 E와 하한만 남긴다. E<150이면 용량 부족으로 종료한다. E≥150이면 N_min=max(100,ceil(2E/5))이며 이후 1단계 실행 등록도 별도 검토 대상이다.

## 병합 뒤 실행

검토된 최신 명세와 같은 커밋의 깨끗한 checkout에서 전용 가상환경에 해당 checkout을 설치하고 저장소 루트에서 실행한다. output은 존재하지 않는 새 파일로 지정한다.

```powershell
python -m pip install -e .
python tools/d104_capacity.py --reports docs/reports --output D104-capacity.json
```

실패 시 산출물을 게시하지 않고 원인을 검토한다. 성공하면 커밋과 용량 결과를 별도 PR에 게시한다. 이번 절차는 펀딩·5분봉·정산 mark·성과 자료를 수집하지 않는다. 펀딩 시각 전수 대조는 별도 1단계 재생 입력 계약으로만 합성 검증한다.
