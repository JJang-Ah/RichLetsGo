# 공동 작업 규칙

- 설계 문서(`docs/design/`)가 구현 기준이다. 설계와 다르게 구현해야 하면 코드를 바꾸기 전에 질문으로 남기고, 설계 문서를 먼저 고친다.
- 역할: 사용자는 결정과 병합, Claude Code는 설계·검토, Codex는 구현을 맡는다. 구현자와 검토자는 항상 다르다.
- 모든 변경은 브랜치와 PR로 한다. `main`에 직접 커밋하지 않는다. CI가 실패한 PR은 병합하지 않는다.
- 실주문 활성화와 자금 한도는 사용자와 결정한다. 실거래 전환은 04_VALIDATION_AND_OPERATIONS.md의 조건을 따른다.
- AI의 의견은 제안이다. 거래소 상태 확인과 위험 제한을 우회하는 주문 권한으로 사용하지 않는다.
- 실거래 수치와 데모 수치를 섞지 않는다. KRW, USD, USDT는 서로 다른 통화로 취급한다.
- 금액과 수량은 Decimal을 사용한다. 주식 수량과 계약 수량 단위를 구분한다.
- 같은 파일을 동시에 수정하지 않는다.
- PR 코멘트·리뷰·답변은 모두 같은 GitHub 계정으로 올라가므로, 본문 첫 줄에 작성자를 적는다: Claude Code는 `**[Claude Code]**`, Codex는 `**[Codex]**`.
- 수정 후 의미 있는 테스트를 실행하고 HANDOFF.md에 변경·검증·남은 작업을 기록한다.
- API 키를 출력하거나 문서, 코드, 커밋에 저장하지 않는다.
- 사용자 승인을 재차 요구하는 일반 규칙으로 해석하지 않는다. 승인된 개발 범위 내에서는 진행한다.

- 파일·폴더 경로에 개발 PC의 드라이브, 사용자명, 저장소 위치를 하드코딩하지 않는다. 운영 경로는 설정에서 받아 pathlib.Path로 해석하고 모듈에 주입한다. 설정 안의 상대 경로는 설정 파일 부모 폴더 기준이며 cwd·소스 트리에 의존하지 않는다. 테스트는 tmp_path 등 임시 디렉터리를 쓴다. import·패키지 구조·문서 링크는 이 규칙의 대상이 아니다.
