# M1-05 거래소 인터페이스와 가상 거래소

- 상태: 구현 완료, Claude Code 검토 대기
- 구현: Codex / 검토: Claude Code
- 브랜치: `task/M1-05-simulated-exchange`
- 근거: 03 3장(ExchangeGateway), 04 3.1절 가상 체결 규칙 (D49), 01 1.4절 (D41 Partial 손절), 03 4.3·5.3절, Bybit 문서(create-order, trading-stop, private order WS)

## 목표

실거래·데모·백테스트가 같은 코드로 돌도록 거래소 인터페이스를 정하고, 그 인터페이스를 따르는 가상 거래소를 만든다. 가상 거래소는 M1 장애 테스트, M2 백테스트, M4 그림자 장부가 함께 쓴다. **세 곳이 같은 체결 규칙을 쓰는 것이 핵심**이다.

## 범위

### 만들 것 (`src/richletsgo/exchange/`)

1. **`ExchangeGateway` 프로토콜** (비동기)
   - 주문: `place_order(request)`, `cancel_order(order_link_id)`, `amend_stop(order_link_id, trigger_price)`
   - 조회: `get_open_orders(symbol)`, `get_order_history(symbol, since)`, `get_executions(symbol, since)`, `get_positions()`, `get_account()`(지갑 잔고와 미실현 손익을 따로 돌려주는 `AccountSnapshot`, D72), `get_instrument(symbol)`
   - 이벤트 스트림: `private_events()` → `OrderEvent | ExecutionEvent | PositionSnapshot` 비동기 반복자, `connected` 상태와 끊김 알림
   - 결과·오류는 구조화된 타입으로 돌려준다(예: `OrderNotFound`, `TooLateToCancel`, `Timeout`, `Rejected(code, msg)`). Bybit 오류 코드 매핑은 M3.
   - 수량은 내부 부호 수량으로 받고, `Side` 변환은 어댑터 안에서만 한다(D53).

2. **`SimulatedExchange`** (`exchange/simulated/`)
   - 입력: 봉 데이터 공급자(OHLC, 펀딩비율), `InstrumentSpec`, 수수료율(메이커·테이커), 슬리피지 모델, 시계.
   - **체결 규칙 (04 3.1절, 그대로 구현)**
     - 신호 봉 종가로는 체결하지 않음. 최초 체결은 다음 봉 시가.
     - 시장가: 다음 봉 시가 ± 슬리피지(불리한 방향), 테이커 수수료.
     - 지정가: 이후 봉이 지정가를 **넘어서야** 체결(닿기만 하면 미체결), 메이커 수수료, 유효 기간 경과 시 취소.
     - 손절(시장가 조건부): 저가(롱)/고가(숏)가 trigger에 닿으면 trigger ± 슬리피지. 갭이면 시가 ± 슬리피지.
     - 진입 봉 안에서 손절가에 닿았으면 손절된 것으로 봄.
     - 한 봉에 손절과 다른 유리한 사건이 함께 가능하면 손절 먼저.
     - 펀딩비: 주입받은 펀딩 기록의 시각에 보유 중이면 정산(D87, 시각을 고정하지 않음). 그 시각에 끝나는 봉의 체결·손절을 먼저 처리한 뒤, 그 시점 보유 포지션에 정산한다. 다음 봉 시가 체결은 펀딩 정산 뒤에 일어난다(04 3.1절 경계 순서).
     - 수량은 `round_qty_down`, 최소 수량 미만 주문은 거절.
   - **Partial 부착 손절 (D41)**: 진입 주문에 손절 파라미터가 있으면, 체결될 때마다 **그 체결 수량만큼** 조건부 손절 주문을 즉시 만들고 `parent_order_link_id`를 채운다. 손절 파라미터가 잘못되면 진입 자체를 거절.
   - **reduce-only**: 포지션을 넘겨 줄이지 않는다. 시장가 reduce-only는 IOC로 처리하고, 장애 주입으로 일부만 체결되게 할 수 있다.
   - **손절 수량 자동 조정**: 포지션보다 손절 합계가 크면 줄인다. 실제 Bybit 규칙은 M3에서 확인하므로, 가상 거래소의 조정 규칙을 설정 가능하게 하고 기본 규칙을 문서화한다. 최소한 "가장 최근 손절부터", "가장 오래된 손절부터", "지정한 부모 주문의 손절부터"(다른 전략의 손절을 먼저 줄이는 경우를 재현, M1-04 D58 테스트용) 세 가지를 지원한다.
   - **단방향·격리**: 계약별 순포지션 하나, 강제청산은 M1에서 모델링하지 않는다(P5 검사는 위험 엔진 몫). 이 한계를 docstring에 적는다.

3. **장애 주입** (`FaultPlan`) — V0 테스트용
   - 주문 응답 유실(거래소는 접수했지만 호출자는 `Timeout`)
   - 조회 반영 지연(접수된 주문이 N번의 조회 동안 open/history에 안 보임)
   - 조회 오류(특정 조회가 오류 반환)
   - 이벤트 순서 바꾸기(execution보다 `Filled`/`Cancelled` 먼저), 같은 이벤트 중복, 취소 경합 시 `Filled` 두 번
   - 개인 이벤트 스트림 끊김(그 사이 이벤트는 스트림에 안 오고 REST 조회에는 보임)
   - 부착 손절의 execution을 부모 연결 주문 이벤트보다 먼저 보내기 (D61)
   - 시장가 IOC 부분 체결·거절
   - 취소 요청에 "주문 없음/늦음" 응답
   - 계획은 선언형으로(어느 orderLinkId·몇 번째 호출에 무엇을) 정의해 테스트가 결정적으로 재현되게 한다.

4. **결정성**
   - 같은 봉 데이터 + 같은 주문 순서 + 같은 FaultPlan → 같은 결과. 난수가 필요하면 시드를 주입한다.

## 구현·호출 계약 (2026-10-21)

- `exchange.contracts`는 `OrderRequest`, `ExchangeGateway`, `Accepted`/`ExchangeError`를 제공한다. `OrderRequest.from_record`로 OMS 주문을 변환한다. 수량은 부호를 유지한다. 오류의 `ErrorCode`를 검사하며, TIMEOUT은 실패 확정이 아니므로 기존 ID로 조회한다.
- `SimulatedExchange`에 상품 규칙, 시계, 초기 잔고, 메이커/테이커 수수료, 슬리피지 함수를 주입한다. 수수료율·슬리피지에 운용 기본값은 없다. 슬리피지는 `(Price, Qty) -> Price`이고 불리한 방향만 허용한다.
- 데이터 공급자가 `advance_bar(bar, funding=...)`로 마감된 봉을 전달한다. 주문 제출 시각이 봉 시작 이하일 때만 체결할 수 있다. 신호 봉을 처리한 후 그 종가 시각에 주문을 제출하면 다음 봉부터 대상이 된다. 시계를 봉 끝으로 이동한 뒤 호출하고, 주문·취소·수정도 같은 순방향 시계로 호출한다. 같은 계약의 겹치는 봉/재처리는 거절한다.
- 기본 지정가 유효 기간은 최초 대상 봉의 끝까지다. `expires_at`으로 명시한 기간은 테스트의 여러 번 부분 체결에도 사용한다. 만료가 봉 내부에 있으면 추측하지 않고 더 작은 봉을 요구한다. 지정가는 엄격한 가격 돌파만 체결하며 가격은 지정가 그대로다.
- 한 봉의 기존 손절을 먼저 처리하고 일반 주문, 새 부착 손절 순서로 처리한다. OHLC는 봉 내부 경로를 알 수 없으므로 보수적인 가정이다. 시장가 execution 시각은 봉 시작, 지정가/손절은 봉 끝 1마이크로초 전의 합성 시각이다. 처리 순서와 시각 순서가 다를 수 있다. 수신 이벤트 순서를 체결 시각의 정렬이라고 가정하지 않는다.
- 펀딩 기록은 해당 봉 끝과 정확히 같은 시각이어야 하고 계약당 한 건만 받는다. 이전 봉 체결·손절 → 경계 펀딩 → 다음 봉 시가 순서다. 봉 내부 펀딩은 더 작은 봉으로 나눈다. 누락 데이터 검사는 M2 호출자 책임이며, 기록이 없다는 이유로 임의의 8시간 펀딩을 만들지 않는다. `funding_payments`는 시각·수량·평가 가격·현금 증감(지급 음수, 수취 양수)을 제공한다. UTC 자정의 `EquityTracker.start_day`는 모든 계약의 경계 처리가 끝난 뒤 호출자가 수행한다.
- 손절 합계 축소 기본값은 NEWEST(최근 생성부터), OLDEST, PREFERRED_PARENT(`preferred_parent` 필수)를 지원한다. **가상 거래소 가정이며 실제 Bybit의 우선순위를 보장하지 않는다. M3에서 대조한다.** 부착 손절은 client ID 없이 exchange ID와 parent ID를 가지므로 취소·수정은 exchange ID도 받는다. `sim-order-` 접두사는 내부 ID용으로 예약한다.
- 평균가·실현 손익·수수료·펀딩은 지갑에, 최신 종가 평가손익은 `AccountSnapshot.unrealized_pnl`에 반영한다. 체결 가격용 OHLC를 손절 판정과 평가에도 쓰는 V0/V1 모델이며 별도 mark/index 가격·격리 증거금·강제청산 모델은 없다.
- `Fault(operation, occurrence, kind, order_link_id=None, value=...)`: operation 전체 호출 또는 지정 ID 호출의 N번째에 한 번 발생한다. `PARTIAL_FILL.value`는 잔량 대비 비율, `HIDE_ORDER.value`는 open/history를 합친 숨김 조회 횟수다. 계획은 불변이고 카운터는 거래소 인스턴스별이다. 실행 중 fault 계획을 바꾸지 않는다.
- `HOLD_ATTACHED`는 부모 진입의 place에 걸며, 자식 손절 execution 뒤에 보류한 연결 이벤트를 내보낸다. 그 전에도 REST에서는 조회된다. `release_held()`를 호출하면 손절 미발동 상태에서도 현재 보류된 연결 이벤트 전부를 생성 순서대로 한 번 방출한다. 부모 체결을 소비한 뒤 호출해 늦은 연결 도착을 재현할 수 있다. 원래 이벤트 내용·시각을 유지하며 주문·체결·잔고는 바꾸지 않는다. 이미 자동 방출한 이벤트는 다시 내보내지 않고, 연결이 끊긴 동안 방출하면 일반 개인 이벤트처럼 버린다. `ORDER_FIRST`/`DUPLICATE`는 이벤트 전송만 바꾸고 장부·REST 체결은 한 번 반영한다. `CANCEL_RACE`는 현재 마지막 종가에 취소와 체결의 경합을 강제하는 테스트 전용 가정이며 정상 봉 체결 모델이 아니다.
- 개인 스트림은 단일 소비자다. `disconnect()` 또는 장애 주입은 `connected=False`와 iterator 종료로 알리며 끊긴 동안 이벤트를 재생하지 않는다. REST로 복구 후 `reconnect()`하고 새 iterator를 구독한다. `drain_events()`는 테스트용 대체 소비 API로 스트림과 함께 소비하지 않는다.
- 실제 네트워크 전송과 OMS/포트폴리오/저널 조립은 M1-06/M3 범위다. `as_gateway`는 strict mypy가 검사하는 프로토콜 적합성 경계다.

검증: 가상 거래소 52개 테스트, 전체 Python 3.12·3.14 각각 475 passed + 28 subtests. ruff check/format, mypy strict(51 소스).
