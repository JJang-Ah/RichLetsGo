# M3-08 텔레그램 문구를 사람이 읽기 쉽게

- 상태: 명세 작성 완료(사용자 방향 승인 2026-11-18, D108), 구현 대기
- 구현: Codex / 검토: Claude Code
- 브랜치: `task/M3-08-telegram-wording`
- 근거: D108, M3-05(텔레그램), M3-06(Watchdog), PR #75(정지 전이 묶음)

## 목표

사용자가 휴대폰으로 알림을 보고 **무슨 일인지, 거래가 막혔는지, 해야 할 일이 있는지** 바로 알 수 있게 한다. 지금은 내부 코드(`ENTRY_PAUSED_SYSTEM query`), UTC ISO 시각, JSON 요약이 그대로 나가고, 시작할 때만 같은 뜻의 알림이 5통 온다.

동작(정지 조건·진입 차단·알림을 보낼지 말지의 판단 기준)은 바꾸지 않는다. **문구, 묶음, 표시 형식만** 바꾼다. 예외는 아래 3번(시작 알림 묶음)과 4번(정보성 알림 묶음)이다.

## 원칙

1. 내부 코드 대신 쉬운 한국어. 메시지 끝에 `(코드 query)`처럼 원래 코드를 짧게 남긴다(조사용).
2. 시각은 모두 한국 시간(KST, `MM-DD HH:MM`). 날짜만 필요하면 `11월 17일`.
3. 환경 표시는 `[데모]` / `[실거래]`. Watchdog은 `[데모 감시]` / `[실거래 감시]`.
4. 맨 앞 아이콘 한 개로 종류를 구분한다.

   | 아이콘 | 뜻 |
   |---|---|
   | ▶️ | 시작·종료 |
   | 🔴 | 새 진입 멈춤(정지 추가) |
   | 🟢 | 멈춤 원인 해결(정지 해제) |
   | ⚠️ | 반복 경고·확인 필요 |
   | 🚨 | Watchdog 경보, 재시작 한도, 보호·장부 이상처럼 사람이 바로 봐야 하는 것 |
   | 💰 | 체결·손절·펀딩 |
   | 📊 | 일일 요약 |
   | ℹ️ | 명령 응답·정보 |

5. 정지가 하나 풀려도 다른 정지가 남아 있으면 **남은 멈춤을 함께 보여 준다**. 원인 하나의 해제를 거래 재개로 오해하지 않게 한다. 남은 것이 없으면 `새 진입 가능`이라고 쓴다.
6. 비밀값(키·토큰·봇 URL)과 원격 예외 원문은 지금처럼 절대 넣지 않는다.

## 범위

### 1. 문구 사전 (`notify/wording.py` 같은 한 곳)

- 정지 종류(`PauseKind`)와 사유(`reason`), Notice `code`를 사람 문구로 바꾸는 표를 한 모듈에 둔다. Telegram·Watchdog·서비스 래퍼가 같은 표를 쓴다.
- 표에 없는 코드는 `⚠️ [데모] 알 수 없는 상태 (코드 xxx)`로 보내고 실패하지 않는다.
- **테스트**: 소스에 나오는 모든 `pause("…")`, `_bad("…")`, `Notice(…, code=…)` 사유·코드가 표에 있는지 검사한다(새 코드를 추가하면서 문구를 빠뜨리면 테스트가 실패).

정지 종류:

| PauseKind | 문구 |
|---|---|
| `ENTRY_PAUSED_MANUAL` | 수동 정지(직접 건 것) |
| `ENTRY_PAUSED_SYSTEM` | 자동 정지 |
| `ENTRY_PAUSED_DAILY` | 오늘 손실 한도 도달 |
| `STRATEGY_PAUSED` | 전략 정지 |
| `HALTED` | 전체 중단 |

주요 사유(나머지도 같은 수준으로 채운다. 종목이 있으면 `BTCUSDT` 같은 이름을 붙인다):

| 사유 | 문구 |
|---|---|
| `operator` | 직접 정지함 |
| `sync` | 장부 대조 중 |
| `bybit_stream` / `stream` | 거래소 실시간 연결 끊김 |
| `bybit_startup` | 시작 점검 중 |
| `query` / `boundary_query` | 거래소 주문 내역 조회 실패 |
| `bybit_history_window` / `history_out_of_range` | 거래소 내역 조회 범위(7일) 초과, 직접 확인 필요 |
| `data` | 전략 계산용 봉 데이터 부족 |
| `clock` | PC 시계 차이가 큼 |
| `db` / `storage` | 저장소(DB) 오류 |
| `journal_uncertain` | 주문 기록 불확실, 확인 필요 |
| `unknown` | 결과를 모르는 주문 있음, 확인 필요 |
| `pending_attribution` / `unbooked` | 장부에 아직 안 맞춘 체결 있음 |
| `replacement_exhausted` | 손절 주문 교체 실패 |
| `actual_liquidation_buffer` / `liquidation_price_unavailable` | 청산가 여유 부족 또는 확인 불가 |
| `bybit_account_settings` | 거래소 계정 설정이 예상과 다름 |
| `bybit_instruments` / `bybit_unknown_instrument` | 상품 정보 확인 실패 |
| `*_mapping` | 거래소 응답 형식이 예상과 다름 |

### 2. 정지 전이 문구

- 추가: `🔴 [데모] 새 진입 멈춤 — <사유 문구>` + 줄바꿈 `남은 멈춤: <목록>`(방금 추가된 것 제외, 없으면 생략).
- 해제: `🟢 [데모] 멈춤 원인 해결 — <사유 문구> (<걸린 시간>)` + 줄바꿈 `남은 멈춤: <목록>` 또는 `새 진입 가능`.
- 같은 묶음 창 안의 전이는 지금처럼 묶되, 표시는 `(1분 동안 3번)` 형식. `(repeated N; ISO .. ISO)` 형식은 쓰지 않는다.
- 지금의 `정지 해소: 정지: …` 이중 접두사를 없앤다.

### 3. 시작 알림 묶음

- 시작할 때 나가는 `Trader startup`, `bybit_stream`, `sync`, `Bybit stream synchronized`, 그 정지 추가·해제 알림을 **한 통**으로 만든다.
  - 준비 완료 시: `▶️ [데모] 프로그램 시작 완료 — 거래소 연결·장부 대조 끝 (N초)` + `남은 멈춤: …`.
  - 시작 후 `unknown_alert_after`(2분) 안에 준비가 안 되면: `⚠️ [데모] 프로그램 시작했지만 아직 준비 안 됨 — <남은 원인>`. 이후는 일반 정지 전이 규칙.
- 정상 종료: `▶️ [데모] 프로그램 종료`.

### 4. 정보성 알림

- `Bybit stream synchronized`, `Bybit clock recovered`처럼 문제 해결을 뜻하는 정보성 Notice는 단독으로 보내지 않는다. 대응되는 정지 해제 문구에 포함되거나 로그에만 남긴다.
- 반복 경고(`WarningBatcher` 요약): `⚠️ [데모] <문구> (1분 동안 28번)`.

### 5. 일일 요약

JSON 대신 줄 단위로:

```
📊 [데모] 11월 17일 요약
손익 0 USDT · 체결 0건 · 한도 사용 0%
AI 비용: 꺼짐
걸려 있는 멈춤: 수동 정지(11-16 21:43부터)
```

- 값의 의미·계산은 그대로(D81 손익 등). 표시 단위만 바꾼다. 비율은 %로.

### 6. 체결·펀딩·키 만료

- 체결/손절: `💰 [데모] 체결 — BTCUSDT 매수 0.010 @ 91,234.5` (손절이면 `손절 체결`). exec_id는 끝에 `(체결 ID 앞 8자리)`.
- 귀속 보류: `⚠️ [데모] 장부에 아직 안 맞춘 체결 — …`, 해소는 `🟢 … 장부 맞춤 완료`.
- 자정 펀딩 대기/확인: `💰 [데모] 자정 펀딩 정산 대기 — 새 진입 멈춤` / `🟢 … 펀딩 정산 확인`.
- 키 만료: `⚠️ Bybit API 키 만료까지 N일 (MM-DD)`.

### 7. 명령 응답

- `/status`: JSON 대신 줄 단위(포지션·손절가, 오늘 손익, 한도 사용률, 걸려 있는 멈춤 목록, 마지막 확정 봉 시각 KST, 키 만료까지). 이월된 P3(/status 사람 문장, 미확인 표시, day_start 설명)를 여기서 함께 처리한다.
- `/resume` 확인: 기록용 최고점·평가액·낙폭·다음 정지 수준·허용 폭을 이름 붙인 줄로. 실제 적용값도 같은 형식.
- `/resolve` 확인 문구: 이월된 P3(거절 확인 문구)를 함께 처리한다.
- 명령 상태(`requested`/`confirmed`/`rejected` 등)는 `요청 받음`/`실행함`/`거절됨`처럼 한국어로.

### 8. Watchdog·서비스 래퍼

| 원인 | 경보(🚨) | 복구(🟢) |
|---|---|---|
| `health_unavailable` | 프로그램 응답 없음 (N분째) | 프로그램 응답 복구 |
| `alive` | 프로그램 종료 중 | 정상 |
| `ready` | 새 진입 준비 안 됨 (N분째) | 준비 완료 |
| `private_ws` | 거래소 실시간 연결 끊김 (N분째) | 연결 복구 |
| `boundary_stale` | 시간 봉 처리가 멈춤 (마지막 MM-DD HH:MM) | 봉 처리 재개 |
| `database` | 저장소(DB) 확인 실패 | 저장소 정상 |
| `disk_low` / `disk_unavailable` | 디스크 여유 부족 (N GB 남음) / 디스크 확인 실패 | 디스크 정상 |
| `restart_limit_<역할>` | <역할> 재시작 한도 도달 — 자동 재시작 멈춤, 직접 확인 필요 | (수동 해제 뒤) 정상 |
| `restart_state_<역할>` | <역할> 재시작 기록 파일 이상 | 정상 |

- 반복 알림은 `(계속됨, N분째)`.
- 서비스 래퍼 정지 알림: `🚨 [데모 감시] Trader 재시작 한도 도달 — 자동 재시작 멈춤, 직접 확인 필요`.
- 같은 원인 묶음(PR #77 P3-2: `ready`와 `private_ws` 두 통) 정리는 이번에 함께 해도 된다.
