## 목표

전략 신호를 계좌 주문으로 바꾸는 과정(신호 → 승인 목표 → 주문 수량)과, 전략별 장부·손절 귀속·청산 절차를 구현한다. 전략 자체(S1·S2 지표)는 M2에서 만들고, 여기서는 신호를 입력으로 받는다.

## 범위

### 만들 것 (`src/richletsgo/portfolio/`, 일부 `oms/`)

1. **신호와 결정** (D43)
   - `MarketSignal`: `signal_id = (strategy, symbol, bar_start, kind)`, 방향, 원래 목표 크기 산출에 필요한 값(진입 예상가, 손절가 등). 계좌와 무관(D56).
   - 결정 기록은 M1-03의 `DecisionStore`((계좌, signal_id) 유일)를 쓴다. 결정 저장과 주문 생성은 위험 게이트의 한 트랜잭션에서 일어난다(D60). 이 작업은 결정에 담을 내용(원래 목표, AI 모드·점수, 승인 목표, 거절 이유)을 채운다.
   - `AiScoreStore`: signal_id별 점수 결과 하나(D56). M1에서는 테스트가 결과를 직접 넣는다.
   - 점수 결과는 `OK(score)`, `TIMEOUT`, `INVALID_FORMAT`, `BUDGET_EXCEEDED`, `STALE_PERIODIC`(주기 평가가 오래됨) 중 하나다. `ai.mode=enabled`에서 `OK`가 아니면 진입하지 않는다(V0 34행). `ai.mode=disabled` → 계수 1.0(03 4.4절). 실제 AI 호출과 비용 집계는 M4.

1-1. **진입 에피소드** (D59, 03 4.1절)
   - M1-03의 `EpisodeStore`를 쓴다. 시작은 위험 게이트가 하고, 이 작업은 **퇴장과 종료 규칙**(D64)을 구현한다.
   - 상태: `OPEN` → `EXITING` → `CLOSED`.
   - `EXITING` 진입: 그 에피소드의 손절 체결, 청산 의도 기록, 외부 감소. 진입 즉시 남은 진입 주문 취소 요청을 낸다.
   - `EXITING` 중 남은 진입 주문이 체결되면, 그 수량에 대해 청산 절차를 이어서 진행한다(CloseIntent 재개 또는 생성).
   - `CLOSED` 조건(모두): 그 전략 보유 0, 에피소드의 모든 진입 주문이 종결 확정(`UNKNOWN`이면 해소까지 대기), 그 주문들의 미반영·귀속 보류 체결 없음.
   - `CLOSED` 전에는 그 (계좌, 전략, 계약)의 새 에피소드와 방향 전환을 막는다(신호는 기록만). 진입 주문이 체결 없이 종결된 경우도 같은 조건으로 `CLOSED`가 된다.
   - 열린 에피소드의 같은 방향 신호는 유지 신호(주문 없음), 반대 방향 신호는 기존 에피소드 청산 의도를 만든다(방향 전환은 청산 확정 후 새 에피소드).

2. **주문 수량 계산** (D53)
   - `차이 = 승인 목표 − (보유 + 예약 + 미반영 체결)` (그 전략 기준).
   - 진입은 `차이`와 `승인 목표`의 부호가 같고 0이 아닐 때만, `|차이|`만큼.
   - 축소는 진입 계산에서 하지 않는다. 방향 전환은 청산 확정(보유 0) 후 새 진입.
   - 거절된 신호, 부분 체결 후 취소된 신호에 보충 주문 없음.

3. **전략 장부** `StrategyBook`
   - 전략·계약별: 보유 수량(부호), 평균가, 실현 손익, 수수료, 펀딩비, 연결된 손절 주문 목록과 수량.
   - M1-02 `apply_execution`의 훅으로 갱신된다. 체결의 전략은 주문의 orderLinkId(진입·청산·보호)나 부착 손절의 `parent_order_link_id` → 진입 주문 → 전략 순으로 찾는다.
   - 불변식 검사 함수: 전략별 손절 수량 = 보유량, 계약별 손절 합계 = 순포지션(청산 진행 중 제외), 장부 합계 = 거래소 포지션(동기화 때).

4. **손절 부착** (D41)
   - 진입 주문 요청에 항상 손절 파라미터(`stopLoss`, `tpslMode=Partial`, `slOrderType=Market`, `slTriggerBy`)를 넣는다. 손절가 없는 진입 요청은 만들 수 없게 한다(타입·생성자에서 강제).
   - 진입 체결 시 거래소가 만든 손절(`ATTACHED_SL`)을 `parent_order_link_id`로 찾아 전략에 연결한다. 체결 수량만큼 손절이 확인되지 않으면 보호 재등록(`PROTECT`) 요청을 만든다.

5. **손절 유지 청산 절차** (D42, 01 1.4절)
   - `CloseIntent` 상태: `RECORDED` → `CLOSING`(그 에피소드의 남은 진입 주문 취소 요청 + 시장가 reduce-only 전송·재시도. 청산 수량 = 보유 − 열린 청산 주문 수량) → `FLAT_CONFIRMED`(체결 내역으로 보유 0 **그리고** 에피소드 진입 주문 모두 종결 확인. 그 사이 진입 잔량이 체결되면 `CLOSING`으로 돌아감) → `PROTECTING_OTHERS`(같은 계약의 남은 전략마다 손절 수량 = 보유량 확인, 부족분 `PROTECT` 요청과 거래소 확인 대기, D58) → `STOPS_CANCELLING`(청산한 전략의 손절 취소) → `VERIFYING`(손절 다시 읽어 불변식 확인) → `DONE`.
   - `PROTECTING_OTHERS`에서 재등록이 정해진 횟수 안에 확인되지 않으면, 보호되지 않은 수량만큼 그 전략을 reduce-only로 줄이는 요청과 알림을 내고, 청산한 전략의 손절은 **취소하지 않는다**.
   - 각 단계에서 다음 행동을 돌려주는 순수 상태 기계로 만든다(거래소 호출은 하지 않음).
   - IOC 부분 체결·거절: 남은 수량으로 재시도, 횟수 초과 시 해당 계약 `ENTRY_PAUSED_SYSTEM` + 알림. **손절 취소 요청은 `FLAT_CONFIRMED` 전에는 절대 만들지 않는다.**
   - 재시작 시 `CloseIntent`를 복원해 남은 단계부터 이어서 한다.

6. **초과 감소·외부 감소 배분** (01 1.4절)
   - 외부 감소는 M1-02가 `EXTERNAL`로 확정한 체결만 대상이다(귀속 보류 중인 체결은 외부 감소로 처리하지 않음, D61).
   - 어떤 전략에도 귀속되지 않는 감소(외부 감소), 또는 한 전략 귀속 감소가 그 전략 보유량보다 큰 경우(청산·손절 동시 발동): 초과분을 S2 → S1 순서로 장부에서 빼고, 줄어든 전략의 손절 초과분 취소 요청을 만들고, 해당 계약 신규 진입을 멈추고(외부 감소만) 알림 이벤트를 낸다.

7. **독립 계좌 인스턴스**
   - 장부·결정·정지 상태·예약을 계좌 ID로 분리해서 같은 코드로 여러 계좌(실제, `shadow_ai`, `shadow_noai`)를 돌릴 수 있게 한다. 신호와 AI 점수는 공유한다(D56). 그림자 장부의 실제 운영 연결은 M4.

### 만들지 않을 것

- S1·S2 지표와 신호 생성 (M2), AI 호출 (M4), 거래소 전송 (M1-05·M3)
