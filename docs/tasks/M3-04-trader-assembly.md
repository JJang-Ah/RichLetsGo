## 목표

M1(위험·장부·주문 관리·동기화)과 M2-02(전략)를 M3-01~03의 실제 연결에 붙여 `RichLetsGo-Trader` 프로세스를 만든다. **백테스트(M2-03)와 같은 처리 순서**를 실시간으로 돈다.

## 범위

### 만들 것 (`app.py`, `health/`)

1. **시작 순서** (03 4.3절 1~11단계 그대로)
   - 설정·비밀 → Oracle·마이그레이션 버전 → 정지 상태 복원 → 개인 WS 선구독·버퍼 → REST 스냅샷 → 반영·재생 → 보호 확인 → 안정화 확인 → 시세 WS → 정지(sync) 해제.
   - `ai.mode=disabled` 고정(M3). 시작 시 환경·AI 모드·설정 해시를 텔레그램으로 알림(M3-05).
2. **실행 루프** (D76 순서를 실시간으로)
   - 확정 봉(`confirm=true`)을 받을 때마다 1시간 경계 T 처리: ① 그 사이 체결·손절 이벤트 반영 확인 → ② 펀딩 기록(D87)이 있으면 반영 → ③ UTC 00:00이면 펀딩 반영 뒤 계좌 스냅샷으로 `start_day`(D72·D85), 일일 정지 해제, 곧바로 위험 재검사 → ④ 신호 S1(일봉, 00:00만) → S2, BTC → ETH → ⑤ 위험 게이트(M1-03) → ⑥ 주문 전송기(M1-06: SUBMITTED 커밋 후 전송).
   - 경계 처리 중 다음 봉이 오면 순서대로 줄 세운다(같은 경계를 두 번 처리하지 않음, signal_id 멱등).
3. **정기 작업**
   - 1분마다 REST 정기 대조(03 4.2절), 미반영 체결·귀속 보류·UNKNOWN 해소 판단 실행(M1-02).
   - 하루 1회 상품·위험 단계 갱신(D79), 수수료 확인 기록.
   - 진입 체결 직후 거래소가 알려 준 **실제 강제청산가**로 02 3.1절 부등식을 다시 확인(D62). 만족하지 않으면 알림 후 그 수량을 줄인다.
4. **상태 확인 주소** (`health/`)
   - `127.0.0.1`의 HTTP 주소 하나: 프로세스 살아 있음, 마지막 확정 봉 시각, 개인 WS 연결 상태, 마지막 Oracle 커밋 시각, 정지 상태 요약. Watchdog(M3-06)만 읽는다. 외부 노출 금지.
5. **종료**: 신호를 받으면 신규 진입을 멈추고 진행 중인 커밋을 마친 뒤 종료. 손절은 거래소에 남아 있으므로 청산하지 않는다(P1).

### 만들지 않을 것

- AI 호출(M4), 그림자 장부 운영(M4), 대시보드(M5)
