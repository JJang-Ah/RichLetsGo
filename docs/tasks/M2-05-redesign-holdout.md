- 상태: 명세 작성(2026-10-26), Codex 검토 대기
- 구현: Codex / 검토: Claude Code
- 브랜치: `task/M2-05-redesign-holdout`
- 근거: D93(검증 데이터 원칙), D94(구성), D95(S1-B + S2-P), D96(사전 등록), 01 1.2a절, M2-02·M2-03·M2-04 코드

## 목표

첫 V1(PR #25, 4개 조합 모두 FAIL) 뒤 다시 설계한 **S1-B + S2-P**를 구현하고, **아직 결과를 보지 않은 2021-06 ~ 2023-09 기간**에서 사전 등록한 조건 그대로 1차 V1을 한 번 판정한다.

## 지켜야 할 원칙 (D93, D96)

- 2023-10 ~ 2026-10 데이터로 S2-P를 돌려 보거나 격자를 고르지 않는다. 그 기간은 설계 참고로 이미 썼다.
- D96의 기간·격자·고정값·최소 거래 수·통과 기준은 **실행 전에 설정 파일로 고정**하고, 캠페인 manifest에 기록한다. 결과를 본 뒤 하나라도 바꾸면 새 가설로 따로 등록하고 이 판정과 섞지 않는다.
- 개발과 테스트는 합성 데이터나 작은 고정 데이터로 한다. 실제 판정 기간 데이터로 시험 실행을 반복하지 않는다(한 번만 실행).

## 범위

### 만들 것

1. **4시간봉 만들기** (`strategy/history.py` 등)
   - 마감된 1시간봉 4개(UTC 00·04·08·12·16·20시 시작)를 묶어 4시간봉을 만든다: 시가 = 첫 봉 시가, 고가·저가 = 최대·최소, 종가 = 마지막 봉 종가, 거래량 합.
   - 4개 중 하나라도 없으면 그 4시간봉을 만들지 않는다(D77 데이터 완전성 검사가 이미 1시간봉을 막지만, 함수도 지어내지 않는다).
   - 마감 판정: 4번째 1시간봉이 마감돼야 한다. 미래 정보 차단 테스트를 M2-02와 같은 방식으로.

2. **S2-P 전략** (`strategy/candidates.py`, `models.py`)
   - 매개변수 `S2PParams(rsi_period, lower, atr_period, stop_atr, target_r, max_hold_bars)`. 기본값 없음, 범위 검사(`0 < lower < 50`, `stop_atr > 0`, `target_r > 0`).
   - 입력: 4시간봉 이력, 그 시점 S1 상태, S2 에피소드 정보(아래 `S2PEpisode`).
   - 진입 신호(에피소드 없을 때): 01 1.2a절 RSI 되돌림. `MarketSignal(kind=ENTRY, entry_price=종가, stop_price=종가 − 방향×k×ATR, limit_price=종가, expires_at=신호 4시간봉 마감 + 4시간)`.
   - 청산 신호:
     - **대기 중**(주문만 있고 체결 없음): S1 방향 전환·FLAT이면 EXIT(대기 주문 취소, PR #27 검토 P1-3a).
     - **보유 중**: 목표가 도달, S1 방향 전환·FLAT, 보유 봉 수 > 최대.
   - **목표가** (PR #27 검토 P1-1): `R_price = |평균 체결가 − 부착 손절가|`, `목표가 = 평균 체결가 + 방향 × m × R_price`. 롱 `종가 ≥ 목표가`, 숏 `종가 ≤ 목표가`. 평균 체결가가 바뀌면 그때 값으로 다시 계산. 손절가는 주문 때 부착한 값 그대로. 장부의 R 배수와 구분해 이름을 짓는다.
   - `S2PEpisode` (PR #27 검토 P1-3d): 방향, 상태(`PENDING` / `OPEN`), 평균 체결가(체결 VWAP), 부착 손절가, 첫 체결이 속한 4시간봉 시작. JSON 왕복. 보유 기간은 첫 체결 4시간봉부터 4시간봉 수.
   - 손절가 ≤ 0 이거나 ATR = 0이면 신호 없음(M2-02 규칙과 같음).
   - Wilder 창(10×n), `required_bars` 확장. **워밍업 기간은 봉 주기별로**: S2-P는 `required_bars × 4시간`(지금 `load_data`·`WalkConfig.warmup_start`의 `× 1시간`을 확장). 격자 전체 최대 워밍업을 manifest에 고정.

3. **지정가 만료·PostOnly의 저장과 전송 경로** (PR #27 검토 P1-2, P2-4)
   - 만료 시각과 주문 정책은 **기존 SUBMITTED 커밋 경로를 그대로 지나야** 한다(어댑터 우회 전송 금지):
     - `MarketSignal.expires_at`(선택) → `EntryRequest` → 위험 게이트가 만드는 `OrderRecord.expires_at`·`OrderRecord.post_only`(새 필드)로 저장한다.
     - 저널·재시작용 `encode_order`/`decode_order`, 메모리 저장소 왕복에 두 필드를 넣는다.
     - `OrderRequest.from_record`가 두 필드를 넘기고, 가상 거래소는 `expires_at`을 쓰고 `post_only`는 받기만 한다(01 1.2a절 체결 모델 한계: 거절 미모델링).
   - 만료 경계의 마지막 1시간봉: 체결 판정 먼저, 남은 잔량은 그 봉 끝 만료(M1-05 현재 동작과 같음을 테스트로 고정).
   - 만료·취소로 체결 없이 끝난 진입은 에피소드를 체결 없이 종료(M1-04). 같은 신호로 다시 넣지 않는다.
   - **부분 체결 뒤 만료**(P1-3b): 잔량만 종료, 보유·부착 손절·에피소드 유지. **취소 경합 늦은 체결**(P1-3c): D64 청산.
   - **후속 의존성**: M3-03 어댑터(PR #29)는 `post_only=True`를 `timeInForce=PostOnly`로 보내고, 거절 응답을 "미체결 포기"(에피소드 체결 없이 종료)로 반환해야 한다. 지금 GTC 고정이면 그 PR에 반영한다.

4. **실행기·검증 연결** (M2-03·M2-04)
   - 실행기가 S2-P를 4시간 경계(00·04·…시)에서만 평가한다. 나머지 1시간 경계에서는 체결·손절·펀딩·위험 처리만 한다(D76 순서 그대로).
   - 실행기는 `S2PEpisode`를 **주문 대기 상태까지** 장부·주문 기록에서 만든다(지금은 체결된 거래만 봐서 대기 주문을 놓침).
   - 구간 이동 검증에 조합 `S1B-S2P`, D96 격자 16개, 최소 거래 수 S2 20을 설정으로 넣는다.
   - **선택 규칙 추가**: 정하기 점수 ≤ 0인 후보는 제외한다. 남는 후보가 없으면 `NO_CANDIDATE`(D96). 설정 항목으로 두되, 첫 캠페인(PR #25) 보고서는 다시 만들지 않는다.

5. **1차 V1 실행 — 한 번 판정 절차** (D96)
   1. 구현, 합성 데이터 전체 경로 검증, Claude 검토를 끝낸다. 이 단계까지 판정 구간 실제 데이터는 수집·조회·실행하지 않는다.
   2. 코드 커밋·설정(D96 전체)·비용·위험 프로필을 고정하고 캠페인 manifest에 기록한다. 계산량은 S2-P 합성 벤치마크로만 추정한다.
   3. 그다음에만 수집(2021-03-15 ~ 2023-09-30, 두 계약 일봉·1시간봉·펀딩)과 실행을 한다. 판정 구간은 `[2021-06-01T00:00Z, 2023-09-01T00:00Z)`, 확인 구간 5개.
   4. 중단 뒤 같은 해시로 이어 하는 것은 같은 판정의 계산 재개로 기록한다. 결과를 본 뒤 코드·조건을 바꾼 재실행은 같은 판정으로 부르지 않고 "관측된 기간 재사용"으로 따로 기록한다.
   5. 보고서를 `docs/reports/`에 남긴다. 첫머리에 "사전 등록 조건(D96), 결과를 본 뒤 바꾸지 않음", manifest 해시, D96의 알려진 한계를 적는다.
