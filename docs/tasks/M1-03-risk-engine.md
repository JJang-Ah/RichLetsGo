## 목표

포지션 크기 계산, L1~L7 한도 검사, 계좌 단위 위험 게이트(검사+예약), 정지 상태와 HALTED 재개를 구현한다. 외부 연결 없이 시계·저장소를 주입받는다.

## 범위

### 만들 것 (`src/richletsgo/risk/`)

1. **위험 설정** `RiskLimits` (불변)
   - 02 7장 Q13의 모든 수치를 필드로 받는다: `risk_per_trade`(r), `daily_loss_limit_usdt`, `max_drawdown_ratio`, `strategy_allocations`(S1·S2 비율, 합 ≤ 1), `consecutive_loss_limit`(N), `cooldown`(T), `max_leverage`, `max_symbol_notional_usdt`, `max_account_notional_usdt`, `liquidation_buffer_ratio`, `slippage_buffer`.
   - **기본값 없음.** 모든 값이 필수이고 생성 시 범위를 검사한다(양수, 비율은 0~1, `max_leverage ≥ 1` — REVIEW 발견 6).
   - 테스트는 테스트 전용 값을 쓴다. 이 값은 운용 권고가 아니다.

2. **크기 계산** `size_entry(...)` (02 3장, P5)
   - 입력: 평가액, 전략, 진입 예상가, 원래 손절가, AI 계수 f(s)(0.5~1.0, AI disabled면 1.0), 수수료율, 슬리피지 가정, `InstrumentSpec`, 레버리지, 방향.
   - 순서:
     1. 손절가를 tick에 맞춘다: 진입가에서 멀어지는 쪽 (M1-01 규칙).
     2. 허용 손실 = 평가액 × r × f(s)
     3. 손절 거리 = |진입 예상가 − 정렬된 손절가| + 슬리피지 + 왕복 수수료(가격 환산)
     4. 수량 = 허용 손실 ÷ 손절 거리 → `round_qty_down`. 0이면 진입 안 함(이유 `BELOW_MIN_QTY`).
     5. 예상 강제청산가를 **02 3.1절 근사식 그대로** 계산하고(MMR은 입력), 02 3.1절 부등식(진입가~강제청산가 거리 대비 여유 b, 등호 허용)을 만족하지 않으면 진입 안 함(`LIQUIDATION_TOO_CLOSE`). 함수 이름이나 docstring에 "근사"임을 밝힌다. 실제 강제청산가 재확인은 M3.
   - 레버리지는 증거금 계산에만 쓰고 수량에 곱하지 않는다(P5, 기존 `test_notional_does_not_shrink_with_leverage` 아이디어 이전).
   - 결과: 부호 있는 수량, 정렬된 손절가, 계산 근거(모든 중간값) — decision 기록용.

3. **한도 검사** `check_limits(intent, state) -> Decision` (02 2장)
   - L1 거래당 위험 (크기 계산에 포함), L2 계약별 노출, L3 계좌 노출·레버리지, L4 전략 일일 한도, L5 계좌 일일 한도, L6 낙폭, L7 연속 손실.
   - 노출은 M1-02의 `exposure()` 값(보유 + 미반영 체결 + 예약)으로 계산한다.
   - **노출을 줄이는 주문은 L1~L3에서 면제**하고, 어떤 정지 상태에서도 막지 않는다(02 공통 규칙, REVIEW 발견 1).
   - 거절 시 어느 단계가 왜 거절했는지 구조화된 이유를 돌려준다.

4. **위험 게이트** `RiskGate` (D46, 02 2.1절)
   - 계좌당 `asyncio.Lock` 하나.
   - `async admit(intent) -> Admission`: 잠금 안의 **한 `UnitOfWork`**에서 (D60)
     1. (계좌, signal_id)의 decision이 이미 있으면 그것과 연결된 주문 ID를 그대로 돌려주고 끝.
     2. 열린 진입 에피소드가 있으면(같은 방향) "유지 신호" decision을 저장하고 주문 없이 끝 (D59).
     3. 현재 노출(진입 주문 기준, D57)·평가액·정지 상태 읽기 → 크기 계산 + L1~L7.
     4. decision 저장(거절도 저장). 통과면 주문 `CREATED` 저장(= 예약 생성)과 에피소드 시작을 함께 저장.
     5. 커밋. 커밋 실패 시 아무것도 남지 않는다.
   - 이를 위해 이 작업에서 저장소 인터페이스 `DecisionStore`((계좌, signal_id) 유일), `EpisodeStore`((계좌, 전략, 계약)당 열린 에피소드 최대 1개)와 메모리 구현을 만든다. 신호·점수 모델과 에피소드 종료 규칙은 M1-04가 채운다.
   - 잠금 안에서 거래소·AI 호출 금지(인터페이스상 받지 않는다).
   - 같은 시각 여러 의도는 호출자가 정한 순서(BTCUSDT → ETHUSDT, 04 3.1절)로 넣는다. 게이트는 받은 순서대로 처리한다.

5. **평가액·손실 추적** `EquityTracker`
   - 입력: 거래소 평가액 스냅샷(시각, 값), 입출금 기록(D21, Q14는 미정 — 입력 인터페이스만).
   - 거래일 시작 평가액(UTC 00:00 경계에서 갱신, Q15 기본 규칙), 일일 손실, 전략별 일일 손실(전략 장부 실현+평가 손익 입력 — 계산 입력은 M1-04가 제공), **기록용 최고점**과 **위험 기준 최고점**(D48) 관리.

6. **정지 상태** `PauseState` (02 5장)
   - 상태 집합: `STRATEGY_PAUSED(전략, 이유, 해제 시각)`, `ENTRY_PAUSED_DAILY`, `ENTRY_PAUSED_SYSTEM(이유)`(이유별로 여러 개), `ENTRY_PAUSED_MANUAL`, `HALTED`. 여러 개가 동시에 걸릴 수 있다.
   - 신규 진입 가능 = 해당 전략·계약에 걸린 정지가 하나도 없음.
   - 자동 해제: 다음 거래일(L5), T시간 후(L7), 원인 해소(SYSTEM).
   - 직렬화/복원 함수(재시작 시 디스크·DB에서 복원 — 저장 자체는 M1-06/M3).
   - 계약 단위 정지(`ENTRY_PAUSED_SYSTEM`에 계약 지정)를 지원한다: UNKNOWN 주문, 미반영 체결 지연, 청산 재시도 초과 등은 해당 계약만 멈춘다.

7. **운영 보호 정책** (V0 33·36행, 순수 함수)
   - `MarketDataGuard`: 입력(계약, 기대 봉 마감 시각, 마지막 확정 봉 시각, 현재 시각, 허용 지연) → 출력(해당 계약 `ENTRY_PAUSED_SYSTEM(data)` 설정/해제, 보충이 필요한 봉 구간). 실제 시세 수신과 보충은 M2·M3.
   - `authorize_command(actor_id, command, allowed_ids)`: 등록되지 않은 사용자의 명령은 거절하고 기록 대상으로 돌려준다. 모든 명령 처리(`request_resume` 등)는 이 검사를 먼저 거친다. 실제 텔레그램 봇은 M3.

8. **재개 명령 처리** (D48, 02 5.1절)
   - `request_resume(actor, at) -> ResumePrompt`: 현재 상태와 재설정 내용(기록용 최고점, 현재 평가액, 낙폭, 다음 정지 수준)을 담은 확인 요청을 만든다.
   - `confirm_resume(prompt_id, actor, at)`: 확인되면 `ENTRY_PAUSED_MANUAL` 해제, `HALTED`이면 위험 기준 최고점 = 현재 평가액으로 재설정. 재설정 이력 레코드를 돌려준다.
   - 확인 없는 재개 경로는 없다. 확인 요청은 만료 시간을 둔다.
