## 목표

후보 전략 4개(S1-A, S1-B, S2-A, S2-B)를 **마감된 봉만 보는 순수 함수**로 구현한다. 같은 코드가 백테스트(M2-03)와 실거래(M3 이후)에서 그대로 돈다.

## 범위

### 만들 것 (`src/richletsgo/strategy/`)

1. **지표** (`strategy/indicators.py`) — 마감된 봉 목록을 받아 마지막 봉 기준 값을 돌려준다. 값이 부족하면(워밍업) `None`.
   - 단순 이동평균 SMA(n)
   - 채널 최고가·최저가 (최근 n개 봉의 high 최대·low 최소). **현재 봉을 포함할지**를 인자로 명시한다. 돌파 판단은 "직전 n개 봉의 채널"과 "현재 마감 봉의 종가"를 비교한다.
   - 볼린저 밴드(n, k): 중심선 SMA(n), 위·아래 = 중심선 ± k × 표준편차(모표준편차, n개)
   - RSI(n): Wilder 방식 평활
   - ATR(n): Wilder 방식, True Range 사용
   - 각 지표의 공식과 워밍업 길이를 docstring에 적고, 손으로 계산한 작은 예시를 테스트 기대값으로 쓴다.

2. **S1 추세 상태** (D66) — 일봉, 계약별
   - S1-A 이동평균 교차: SMA(fast) > SMA(slow) → `LONG`, < → `SHORT`, 같으면 직전 상태 유지. 워밍업 중 `FLAT`.
   - S1-B 채널 돌파: 종가 > 직전 N일 최고가 → `LONG`, 종가 < 직전 N일 최저가 → `SHORT`, 그 밖에는 직전 상태 유지. 워밍업 중 `FLAT`.
   - 출력: 추세 상태와 함께, 상태가 `LONG`/`SHORT`이면 그날의 S1 **시장 신호**(`MarketSignal`, signal_id = (S1, 계약, 봉 시작, kind))를 낸다(01 2.2절: 추세가 유지되는 동안 매일). 진입 여부는 에피소드 규칙(D59)이 정한다.

3. **S1 손절** (D68)
   - 초기 손절: 롱이면 직전 M일 최저가, 숏이면 직전 M일 최고가.
   - 추적: 일봉 판단마다 새 채널 값이 유리한 쪽(롱은 위, 숏은 아래)으로 움직였을 때만 손절을 옮긴다. 불리한 방향으로는 옮기지 않는다.
   - 출력은 "원하는 손절가"다. tick 정렬과 크기 계산은 M1-03, 실제 수정 주문은 M1-04가 한다.

4. **S2 신호** (D66, D67) — 1시간봉, 계약별, S1 추세 상태를 입력으로 받는다
   - S1이 `FLAT`이면 신호 없음. S1 방향과 같은 방향으로만 진입 신호(D14).
   - 아래에서 `t`는 현재 마감 봉, `t-1`은 직전 봉이다. 밴드·RSI는 **각 봉 시점에서 그 봉까지의 데이터로 계산한 값**이다(직전 봉 비교에 현재 밴드를 쓰지 않는다).
   - S2-A 볼린저 진입: 롱 `close[t-1] < lower[t-1]` **그리고** `close[t] >= lower[t]`. 숏 `close[t-1] > upper[t-1]` **그리고** `close[t] <= upper[t]`. 청산: 롱 `close[t] >= mid[t]`, 숏 `close[t] <= mid[t]`.
   - S2-B RSI 진입: 롱 `rsi[t-1] < low` **그리고** `rsi[t] >= low`. 숏 `rsi[t-1] > high` **그리고** `rsi[t] <= high`. 청산: 롱 `rsi[t] >= neutral`, 숏 `rsi[t] <= neutral` (`low`, `high`, `neutral`은 매개변수).
   - 최대 보유 봉 수를 넘으면 청산 신호.
   - S1 추세가 바뀌면 S2 청산 신호(01 1.2절).

5. **S2 손절** (D68): 진입 예상가 ∓ K × ATR(1시간봉, n). 추적 없음.

6. **매개변수**
   - 각 전략의 매개변수를 불변 dataclass로 정의한다(예: `S1AParams(fast, slow, exit_channel)`). 값 범위를 생성 시 검사한다(예: fast < slow). **기본값을 두지 않는다**(M2-04가 격자에서 고른다).

7. **신호 타입** (M1-04 병합 후 확정)
   - M1-04의 `MarketSignal(strategy, symbol, bar_start, kind, direction, entry_price, stop_price, limit_price)`를 쓴다. 타입을 따로 만들지 않는다.
   - `kind`는 `ENTRY` 또는 `EXIT`. `MarketSignal`은 `EXIT`에도 가격 두 개를 요구하므로 규칙을 정한다: `EXIT`의 `entry_price`는 그 봉 종가, `stop_price`는 S1이면 현재 원하는 손절가, S2면 진입 때 손절가. 위험 게이트는 퇴장 신호로 크기를 계산하지 않는다(M1-04 `is_exit`).
   - S1의 추세 전환은 반대 방향 `ENTRY` 신호로 나타난다. 라우터가 기존 에피소드의 청산 의도를 만든다(M1-04).

8. **입력·상태 계약** (M3-04 경계 저장과 맞춤)
   - S1: 계약의 마감 일봉 목록 + **직전 S1 상태**(추세, 현재 원하는 손절가)를 받아 새 상태와 신호를 돌려준다. 추적 손절은 직전 손절가보다 유리할 때만 바뀐다.
   - S2: 계약의 마감 1시간봉 목록 + **그 시점의 S1 상태** + **열린 S2 에피소드 정보**(없으면 `None`: 방향, 진입 봉 시작, 진입 때 손절가)를 받는다. 청산 신호(중심선·중립·최대 보유·추세 전환)는 열린 에피소드가 있을 때만 낸다. 진입 신호는 에피소드가 없을 때만 낸다.
   - 상태와 출력은 불변 dataclass이고 JSON으로 왕복할 수 있어야 한다(M3-04 ④단계가 저장·복원). 같은 입력이면 같은 출력(결정적).

9. **추적 손절 연결** (M1-04·06 보완, 점검에서 발견)
   - 01 1.4절 "추적 손절: 손절 trigger를 amend, 실패하면 기존 손절 유지하고 다음 판단 때 재시도"를 실행할 경로가 병합된 코드에 없다. M1-04 `ActionKind`에 trigger 수정 작업이 없고, M1-06 `OrderSender.amend(trigger=…)`는 있지만 부르는 곳이 없다.
   - 추가: `PortfolioService.trail_stop(uow, strategy, symbol, desired: Price)`.
     - 열린 에피소드가 있고 청산 의도가 없을 때만 동작한다.
     - tick 정렬: 롱 손절은 내림, 숏 손절은 올림(보수적, M1-03 정렬 함수 재사용).
     - 정렬한 값이 장부의 `stop_price`보다 **유리할 때만** 장부 `stop_price`를 바꾸고, 그 전략의 확인된 손절(`ATTACHED_SL`·`PROTECT`, OPEN/부분 체결)마다 새 작업 `AMEND_STOP(order_key, trigger)`을 낸다.
     - 미확인 손절(CREATED/SUBMITTED/UNKNOWN)은 확인된 뒤 다음 판단에서 맞춘다. 새로 거는 `PROTECT`는 이미 갱신된 `stop_price`를 쓴다.
   - M1-06 동기화기: `AMEND_STOP` → `sender.amend(trigger=…)`(저널 대상). 실패·불명이면 기존 손절 유지, 다음 판단에서 다시 낸다(새 작업 키). 재생 규칙은 D90과 같다(과거 목표 재전송 금지).
   - 가상 거래소 `amend_stop(trigger)`는 이미 있다. M2-03 백테스트도 이 경로로 추적 손절을 반영한다.
   - 이 항목은 돈이 오가는 경로라 전략 코드와 **커밋을 나누고**, PR 설명에 따로 적는다.
