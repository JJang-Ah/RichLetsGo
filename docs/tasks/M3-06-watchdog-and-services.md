# M3-06 Watchdog·Windows 서비스

- 상태: 명세 작성 완료, 검토 대기 (Q22 결정 필요)
- 구현: Codex / 검토: Claude Code
- 브랜치: `task/M3-06-watchdog-and-services`
- 근거: 03 2장(프로세스 구성), D31, D36, D74, 00 P1, 04 7장(PC 운영)

## 목표

Trader가 멈추거나 Oracle이 죽어도 사용자가 알 수 있게 하고, PC가 재부팅되면 서비스가 순서대로 다시 올라오게 한다.

## 범위

### 만들 것

1. **Watchdog** (`richletsgo_watchdog`)
   - 별도 프로세스. 주문 권한 없음, Oracle에 의존하지 않음(03 2장).
   - 일정 간격으로 Trader health 주소(M3-04)와 Oracle 접속(가벼운 질의)을 확인한다. 응답 없음·오래된 확정 봉·WS 끊김 지속·Oracle 실패를 텔레그램으로 알린다(봇 토큰은 자격 증명 관리자, 발송 전용).
   - 같은 장애는 묶어서 알리고, 복구되면 복구 알림.
   - 디스크 여유가 기준 아래로 내려가면 알림(04 7장).
2. **Windows 서비스 등록** (Q22: 제안 NSSM)
   - 서비스 3개: `RichLetsGo-Trader`(Oracle 서비스에 의존), `RichLetsGo-Watchdog`(의존 없음), 대시보드는 M5.
   - 자동 시작, 비정상 종료 시 재시작(간격·횟수 제한), 표준 출력은 로그 폴더로.
   - 등록·해제 PowerShell 스크립트(`ops/windows/`), 설정 파일 **절대 경로**를 서비스 인자로 넘긴다(03 3.1절).
   - 실행 계정: 사용자 계정(자격 증명 관리자 항목을 읽어야 하므로). 관리자 권한 필요한 단계는 스크립트가 알려 준다.
3. **작업 스케줄러**: 매일 Oracle 백업(M3-02 스크립트), 14일 지난 백업 정리.
4. **운영 점검 스크립트**: 절전 꺼짐, 시간 동기화 상태, 유선 연결, 서비스 상태, 디스크 여유를 한 번에 보여 주는 PowerShell(04 7장 체크리스트 자동 확인). 바꾸지는 않고 보여 주기만 한다.

### 만들지 않을 것

- 원격 재시작·원격 청산(D27)

## 완료 조건

- [ ] Watchdog: 가짜 health·Oracle로 각 장애 → 알림 1회, 복구 → 복구 알림, 반복 장애 묶음
- [ ] Watchdog이 Oracle 없이도 시작·알림 가능
- [ ] (수동) 서비스 등록 후 PC 재부팅 → Oracle → Trader 순서로 올라오고, Trader가 시작 순서(03 4.3절)를 통과해 진입이 열리는지 기록
- [ ] (수동) Trader 프로세스 강제 종료 → 서비스 재시작 → 동기화 복구, Watchdog 알림 확인
- [ ] (수동) 운영 점검 스크립트 결과 첨부

## 검토 포인트

- 서비스 재시작이 동기화 전에 진입을 열지 않는지(시작 순서 준수)
- 재시작 반복(크래시 루프) 시 알림·중단 조건
