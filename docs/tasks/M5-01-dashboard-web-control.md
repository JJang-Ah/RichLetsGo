# M5-01 웹 대시보드와 웹 제어

- 상태: 명세 작성(2026-11-11), Codex 검토 대기
- 구현: **M5-01a 화면(읽기)**은 Claude Code, **M5-01b 제어 API(Trader 쪽)**는 Codex. 검토는 서로 바꿔서 한다(D86·D100: 명세를 쓴 사람은 다른 사람의 검토를 거친 뒤에 구현한다)
- 브랜치: `task/M5-01a-dashboard`, `task/M5-01b-control-api`
- 근거: **D106**(웹 제어 허용), D73(FastAPI + 간단한 HTML), D27(명령 범위), D48·D84(재개 재확인), D54(`/resolve`), **D105**(SQLite, 읽기 전용 연결), 03 7장, M3-05 명령 표

## 목표

이 PC의 브라우저에서 운영 상태를 한눈에 보고, **텔레그램과 같은 명령만** 웹에서도 실행한다. 웹 제어는 텔레그램 명령과 **같은 처리 경로**를 지나므로 위험 검사·재확인 규칙을 건너뛸 수 없다.

## 일정 (사용자 결정 2026-11-11, 05의 M5 순서 예외)

- 화면은 지금 만든다. 저장소(M3-02)가 없으므로 처음에는 **가짜 데이터 공급원**으로 만들고, M3-02가 병합되면 SQLite 읽기 공급원으로 바꾼다.
- 제어 API(M5-01b)는 M3-05 명령 처리와 함께 만든다. 그 전까지 화면의 제어 버튼은 "Trader 미연결"로 비활성화한다.

## 구조

```
브라우저 ──HTTP──▶ Dashboard (127.0.0.1:대시보드 포트)
                      │ 읽기: SQLite 읽기 전용 연결 (D105, mode=ro)
                      │ 제어: Trader 제어 API 호출 (토큰)
                      ▼
                   Trader 제어 API (127.0.0.1:제어 포트) ──▶ CommandService ◀── 텔레그램
```

- Dashboard는 **DB에 쓰지 않는다.** 명령 기록(`commands`)도 Trader가 쓴다. 그래서 DB에 기록하는 프로세스는 계속 Trader 하나다(D105 전제).
- `CommandService`(M5-01b)는 텔레그램(M3-05)과 웹이 함께 쓰는 명령 처리기다. 권한 확인(`authorize_command`), 재확인 단계, 실행, `commands` 기록(`source` = telegram / web)을 한곳에서 한다.

## 보안

| 위험 | 대책 |
|---|---|
| 외부에서 접속 | 두 서버 모두 `127.0.0.1`에만 연다. `0.0.0.0` 설정은 시작 시 거부한다 |
| DNS 재바인딩 | `Host` 헤더가 `127.0.0.1:<포트>` 또는 `localhost:<포트>`가 아니면 거부 |
| 다른 사이트가 몰래 요청(CSRF) | 제어 요청은 POST만 허용. 세션마다 CSRF 토큰을 확인하고, `Origin`이 대시보드 주소가 아니면 거부. 쿠키는 `HttpOnly`, `SameSite=Strict` |
| 이 PC의 다른 프로그램이 제어 | **제어는 접근 코드로 로그인한 세션만** 가능. 접근 코드는 자격 증명 관리자(`richletsgo/dashboard-access`)에 저장하고, 화면·로그·설정 파일에 남기지 않는다. 보기만 하는 화면은 로그인 없이 열린다. 로그인 실패가 연속 5회면 10분 잠근다 |
| Dashboard ↔ Trader 위조 | Trader 제어 API는 자격 증명 관리자의 제어 토큰(`richletsgo/control-token`)을 헤더로 확인한다. 토큰은 시작 시 읽고 응답·로그에 넣지 않는다 |
| 실수로 누름 | 재확인이 필요한 명령은 2단계다. 1단계 응답으로 확인 화면과 일회용 확인 번호(60초 만료)를 받고, 2단계에서 그 번호로 실행한다. 확인은 요청한 세션만 할 수 있다 |
| 원격에서 모르게 실행 | 웹에서 실행한 명령은 결과와 함께 **텔레그램으로도 알린다** |

## 명령 범위 (D106: 텔레그램과 같음)

| 명령 | 웹 | 재확인 |
|---|---|---|
| 상태 보기 | 대시보드 화면 자체 | 없음 |
| 신규 진입 정지 (`/pause`) | 버튼 | 없음 |
| 재개 (`/resume`) | 버튼 → `ResumeService` 재확인 화면(기록용 최고점, 현재 평가액, 낙폭, 다음 정지 수준, 허용 폭) → 확인 | 필수 (D48·D84) |
| 미체결 진입 주문 취소 (`/cancel`) | 버튼. 손절은 유지 | 필수 |
| UNKNOWN 수동 확정 (`/resolve`) | 주문 목록의 UNKNOWN 행에서 실행 | 필수 (D54) |

**넣지 않는 것**: 주문 넣기, 전체 청산(D27: Bybit 앱에서), 위험 한도·설정 변경, API 키 관리, 서비스 시작·종료.

## 화면 (M5-01a)

모든 시각은 한국 시간으로 보여 주고, 내부 값은 UTC 그대로 둔다. 환경(DEMO / LIVE)을 화면 맨 위에 항상 크게 표시하고, LIVE는 색을 달리한다.

1. **개요**: 정지 상태와 이유, 평가액·오늘 손익(D81)·낙폭, 한도 사용률(L1~L7), 마지막 확정 봉·체결 시각, Trader 연결 상태, 키 만료까지 남은 날
2. **포지션**: 전략별 장부 포지션, 손절가, 손절까지 거리, 거래소 손절 수량 = 보유량 여부
3. **평가액 그래프**: 평가액과 낙폭(기간 선택: 1일·7일·30일·전체)
4. **주문·체결**: 최근 주문(상태별 필터, UNKNOWN 강조), 체결 목록
5. **기록**: 알림, 명령(출처 telegram/web, 결과), 정지 이력
6. **결정과 AI**: decision별 AI 점수·근거·비용 누계(M4 이후. 그 전에는 "AI 비활성" 표시)
7. **제어**: 위 명령 표의 버튼(로그인 세션만, 재확인 포함)

- 화면은 서버에서 HTML을 만들고(Jinja2), 자동 새로고침은 짧은 주기(예: 10초)의 가벼운 JSON 조회로 한다. 그래프는 서버가 만든 SVG로 그려 외부 CDN 없이 동작하게 한다.
- 휴대폰 너비에서도 깨지지 않게 만든다(같은 PC 안에서만 접속하더라도 창을 좁혀 볼 수 있으므로).

## 기술

- FastAPI, Uvicorn, Jinja2 (런타임 의존성 추가. 이유: D73에서 정한 웹 구성). 다른 프레임워크·빌드 도구는 쓰지 않는다.
- 데이터 공급원은 인터페이스(`DashboardSource`)로 두고 가짜 구현과 SQLite 읽기 구현을 바꿔 끼운다. 화면 코드는 DB를 직접 열지 않는다.
- Windows 서비스 `RichLetsGo-Dashboard`(M3-06)로 실행한다. Trader가 꺼져 있어도 화면은 뜨고, 제어 버튼만 비활성화한다.
