# M2-06 새 종목 사전 등록 V1 (S1-B 주 판정, S2-P 부 판정)

- 상태: 명세 작성(2026-10-28), Codex 검토 대기
- 구현: Codex / 검토: Claude Code
- 브랜치: `task/M2-06-new-symbol-validation`
- 근거: D97(이 작업의 결정), D93(검증 데이터 원칙), D95(S1-B·S2-P 정의), D96·PR #31(BTC·ETH 판정 INDETERMINATE), D88(위험 프로필·통과 기준), M2-04·M2-05 코드

## 목표

D96 판정(PR #31)에서 S1-B는 이익(+388.8 USDT), S2-P는 사실상 0(+2.26 USDT, 32거래)이었다. BTC·ETH의 2021-03 ~ 2026-10은 이제 모두 관측된 기간이다. 그래서 **아직 아무도 보지 않은 데이터인 새 종목 4개**에서, 전략 정의를 바꾸지 않고 한 번만 판정한다.

- **주 판정**: S1-B 단독(S2 끔). 데모 운영(M3-07) 진입 여부를 이것으로만 정한다.
- **부 판정**: S1-B × S2-P 조합(D96과 같은 격자). 통과해야 데모에서 S2-P를 켤 수 있다. 실패해도 주 판정에는 영향이 없다.

## 지켜야 할 원칙 (D93, D96, D97)

- **새 종목 가격 데이터는 사전 등록 전에 수집·조회·실행하지 않는다.** 종목 선정은 가격이 아닌 메타데이터(상품 정보·현재 24시간 거래대금)로만 한다.
- S1-B·S2-P의 규칙·격자·고정값은 D95·D96 그대로다. 결과를 본 뒤 하나라도 바꾸면 새 가설이며, 이 판정과 섞지 않는다.
- 두 판정(주·부)은 **같은 사전 등록, 같은 수집 데이터(같은 `data_hash`)** 로 한 번에 계산한다. 한쪽 결과를 보고 다른 쪽 조건을 바꾸지 않는다.
- 개발과 테스트는 합성 데이터로 한다.

## 범위

### 만들 것

1. **종목 선정 도구** (`tools/select_universe.py`)
   - Bybit 공개 API의 `instruments-info`(linear)와 `tickers`(linear)**만** 읽는다. kline·펀딩 이력은 읽지 않는다(테스트로 고정: 허용 엔드포인트 외 호출 시 실패).
   - 규칙(D97, 기계적으로 적용):
     1. `contractType = LinearPerpetual`, `quoteCoin = USDT`, `status = Trading`
     2. `launchTime < 2022-01-01T00:00Z`
     3. 제외: BTCUSDT·ETHUSDT, 기초 자산이 스테이블코인·법정화폐·금 연동인 것(USDC, USDE, FDUSD, DAI, TUSD, PAXG, XAUT 등 목록을 도구에 상수로 고정), 기초 자산 이름이 숫자로 시작하는 것(`1000…` 배수 계약)
     4. `turnover24h` 내림차순으로 정렬하고 상위 **4개**를 고른다. 같으면 심볼 이름순.
   - 출력: 선정 결과 JSON(규칙 버전, 응답 원본의 정규화 사본, `captured_at` UTC, 후보 전체 순위표, 선정 4개, `codec.digest`). 사람용 요약은 Markdown.
   - **한 번만 실행**하고, 결과를 이 작업 PR에 첨부한다. 선정 뒤에는 종목을 바꾸지 않는다(수집 중 무결성 실패가 나도 교체하지 않고 INVALID_DATA로 받아들인다).

2. **종목 범위 일반화** (지금은 BTC·ETH 2개 고정)
   - `Symbol`에 선정된 4개를 추가한다(선정 결과 JSON과 같은 이름).
   - 2개 고정 가정을 걷어 낸다: `BacktestRun`의 "BTCUSDT and ETHUSDT exactly once" 검사 → 설정된 종목 목록(정렬·중복 없음·1개 이상), `campaign.py`·`portfolio/service.py`의 `for symbol in Symbol` → 설정된 종목, `statistics.py`의 계약별 분해 → 실행 종목.
   - 연구 설정 `[backtest] symbols`로 종목 목록을 받고 manifest identity에 넣는다.
   - 데모·실거래 설정(`[bybit] symbols`)은 이번에 바꾸지 않는다. 지금처럼 BTC·ETH만 허용하고, 데모 종목은 Q26에서 정한다. 다만 enum이 늘어도 서비스가 설정 밖 종목을 순회하지 않음을 테스트로 고정한다.

3. **S2 끔 모드** (주 판정용)
   - 격자에 S1 후보만 있는 조합 `S1B`를 허용한다(S2 매개변수 없음). 실행기는 S2 신호를 만들지 않는다.
   - 위험 프로필은 D88 그대로 둔다(S1 배분 0.6, S2 배분 0.4는 쓰지 않고 비워 둠). 배분을 S1에 몰아주지 않는다.
   - 보고서는 S2 분해를 빈 값으로 둔다. 최소 정하기 거래 수는 S1만 검사한다.

4. **부 판정 통과 조건 추가**
   - `pass_criteria`에 전략별 최소 순손익을 선택 항목으로 추가한다: `min_strategy_net_pnl_usdt = { S2 = "0" }`. 부 판정은 D88 기준 + **확인 구간 합계 S2 순손익 > 0**이어야 PASS다.
   - 주 판정에는 이 항목을 넣지 않는다.

5. **기술용 기간 분해** (판정 기준 아님)
   - 보고서에 확인 구간 성과를 `2023-10-01` 앞뒤로 나눈 표를 추가한다. S1-B를 고를 때 BTC·ETH의 2023-10 이후 결과를 봤기 때문이다(D97 알려진 한계). 판정에는 쓰지 않는다.

6. **`v1:` 계약 확장** (M3-01·M3-04 후속, 이 작업에서는 명세만)
   - S1 단독 보고서(`S1B` 조합)를 근거로 할 때는 설정 `[strategy.S2] enabled = false`이고, 로더는 그 보고서의 `S1B` PASS와 같은 확인 구간에서 선택된 S1 매개변수 일치를 확인한다.
   - S2-P를 켜려면 부 판정 보고서(`S1B-S2P`)가 PASS여야 하고, 기존 쌍 검증 규칙을 그대로 따른다.

7. **2번 판정 실행 — 한 번 판정 절차** (D96 절차 그대로)
   - (a) **사전 등록 게시**: 구현·합성 검증·Claude 검토·병합 뒤, 코드 커밋, 선정 결과 JSON 해시, 두 판정의 설정 전체, 비용, 수집 범위, 알려진 한계를 담은 사전 등록 문서와 해시를 PR에 먼저 게시한다. 계산량은 6종목 합성 벤치마크로 추정하고 `max_compute_hours`를 그 값으로 정한다.
   - (b) **수집과 고정(한 번)**: 4종목 일봉·1시간봉·펀딩, `[2022-01-01T00:00Z, 2026-10-01T00:00Z)`. 무결성 검사·스냅샷 고정만 하고 성과 계산은 하지 않는다.
   - (c) **최종 manifest 게시**: 두 판정 각각의 manifest(같은 `data_hash`, 같은 사전 등록 id)를 계산 전에 PR에 게시한다.
   - (d) **판정 계산**: 주 판정 → 부 판정 순서로 각 1회. 중단되면 같은 manifest로만 재개한다.
   - 보고서 2개와 각 본문 JSON을 `docs/reports/`에 남긴다. 첫머리에 사전 등록 조건, 해시, D97 알려진 한계를 적는다.

- BTC·ETH 재판정, 데모·실거래 종목 변경(Q26)
