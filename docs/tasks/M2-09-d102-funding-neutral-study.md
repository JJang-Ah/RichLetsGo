## 목표

D98(S2-M)·D101(S1-B 분산)은 1단계 NO_GO였다. D102는 시장 방향을 맞히지 않고, 같은 시각의 종목들을 펀딩비 순으로 줄 세워 롱·숏을 같은 금액으로 묶는 바구니가 비용 뒤에도 수익을 내는지 확인한다. 결과는 04 3.5 6의 진행 기준(go/no-go) 하나다. 판정이 아니라 설계 참고다.

## 지켜야 할 원칙

1. **새 수집 없음.** D98 설계용 풀 DB(data_hash `42acf4dfb41f5d9eff49c02c73a37cc5bc8d6c3d48de04b42382d0b04a08bc6c`)만 읽는다. 판정용 풀 데이터는 요청·조회하지 않는다. 네트워크 코드 없음.
2. **DB는 읽기 전용**(`Store(readonly=True)`, `mode=ro`). D98 freeze 기록을 바꾸지 않는다.
3. 조건(격자·고정값·비용·진행 기준)은 사전 등록으로 먼저 게시하고 연구는 한 번만 실행한다. 결과를 본 뒤 하나라도 바꾸면 새 가설이다.
4. 개발·테스트는 합성 데이터로만 한다. **실제 DB로 시험 실행하지 않는다.**
5. **D98·D101 결과 재현성 유지.** `research/d98/`·`research/d101/`의 결과 계산을 바꾸지 않는다. 공통 함수는 import해서 쓴다.

## 만들 것 (09a)

- 새 패키지 `src/richletsgo/research/d102/`, CLI `tools/d102_study.py`.
- **재사용** (import)
  - D98: 풀 파일 검증, 자산 키·동시 활성 계약 선택, 데이터 수명·폐지(`E_a`) 처리, 범위 판정 함수, data_hash 계산(`audit._audit`), D99 등급, 펀딩 주기 판정, 잠금·LF 출력, `Store(readonly=True)`.
  - D101: 읽기 전용 DB 확인(`verify_frozen_dataset`)과 등록·checkout 검증 구조. D101 함수가 D101 정책·경로에 묶여 있으면 D102 쪽에 같은 구조를 따로 둔다(PR #51 P2와 같은 경계).
- **새로 만들 것**
  - `eligibility.py`: 매일 UTC 00:00 격자에서 `(계약, t)` 단계 1~4 분류(04 3.5 3). 출력은 t별 자격 종목과 그 종목의 F(L = 1일, 7일), D99 등급.
  - `funding.py`: 펀딩 점수 F와 유효 조건(창 `(t − L, t]`, 연속 간격 ≤ 8h, 창 직전 정산부터 검사, `t − 마지막 정산 ≤ 8h`, 주기 ∈ {1, 2, 4, 8}h, 8시간 환산 평균).
  - `basket.py`: 재조정 시각마다 다리 구성(n < 25 → 바구니 부족, `k = floor(0.2n)`, 동률 이름순), 목표 비중, 직전 비중과의 차이로 비용 계산.
  - `period.py`: 기간 `[t, t+H)` 손익. 가격 몫(시가 대 시가), 펀딩 몫(`t < τ ≤ t+H`, `O(τ)/O(t)` 비율), 폐지 `E_a` 청산(그 뒤 현금), 결과 무효(종목 기여 0, 재분배 없음, 비용 유지; 한 다리 전체가 무효면 기간 무효), 기간 종류(정상·현금·무효)는 04 3.5 4절 표.
  - `study.py`: 조합 4개를 같은 자격 표에서 계산하고, 기간 수익 시계열·기술용 출력·진행 기준(04 3.5 6·7)을 만든다.
  - `statistics.py`: 04 3.5 6의 식을 그대로 구현한다(유효 기간 = 정상 + 현금, 표본 표준편차 n − 1과 `s = 0`·`n < 2` 처리, 상위 1% 기간 제거, 연도 기준, `E_0 = 1` 복리 낙폭과 파산, 기준 5의 집합 S·분모 n, 4개 중 2개).
- **계산 구조**: 자격 표는 계약 단위로 계산(worker 병렬 가능)하고, 바구니는 t 순서로 한 번에 계산한다(종목 간 순위가 필요). 메모리는 t별 자격 표(시각 × 종목의 작은 값)만 들고, 1시간봉 전체를 한꺼번에 올리지 않는다. 1 worker와 다중 worker의 body digest가 같아야 한다.
- **출력**: `backtest_results/d102-study/<등록 digest>/`에 다음 파일을 둔다. 모두 `newline="\n"`.
  - `D102-study.json`: body + execution, body digest
  - `D102-study.md`
  - `D102-study-periods.jsonl`: 조합·기간마다 t, 종목 수, k, 롱/숏 목록, 가격 몫, 펀딩 몫, 비용, 순수익, 무효 종목
  - `D102-study-positions.jsonl`: 종목·기간마다 비중, d, g, f, 폐지·무효 사유
- **Markdown 수치 표현**: 표의 숫자는 JSON과 같은 정규화 표현을 쓰거나, 완료 결과 재호출 검증이 표현 차이로 거절하지 않게 한다(PR #54 P3: D101의 `_completed`가 끝자리 0 차이로 MD 바이트 비교에서 거절할 수 있었다).
- **동률 정렬**: 심볼 이름순은 문자열 비교로 한다(PR #52 P3: `-ord` 튜플은 접두어 관계 이름의 순서를 뒤집는다).
