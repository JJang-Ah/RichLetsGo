# 검증 단계와 운영

결정 번호는 [00_DECISIONS.md](00_DECISIONS.md)를 따른다. 각 단계는 통과 조건을 **시작 전에** 기록하고, 결과를 본 뒤에 조건을 낮추지 않는다. 조건을 바꿔야 하면 이유와 날짜를 남기고 해당 단계를 처음부터 다시 한다.

## 1. 단계 개요

| 단계 | 환경 | AI | 통과하면 |
|---|---|---|---|
| V0 코드 검증 | 가상 거래소 | 가짜 응답 | V1 |
| V1 백테스트 | 과거 데이터 (SQLite) | 제외 | V2 |
| V2 데모 모의투자 | Bybit 데모 계정 + Oracle `RLG_DEMO` | 적용 | V3 |
| V3 실거래 | Bybit 실계정 + Oracle `RLG_LIVE` | 적용 | 운영 계속 |

## 2. V0 코드 검증

단위 테스트 외에 가상 거래소로 아래 상황을 재현하고, 기대 동작을 테스트로 고정한다.

| 상황 | 기대 동작 |
|---|---|
| 주문 전송 후 응답 없음 | `UNKNOWN` → orderLinkId로 조회 → 확정. 중복 주문 없음 |
| UNKNOWN 조회 결과가 부분 체결 | 체결 내역 반영 후 `PARTIALLY_FILLED`로 추적, 예약은 남은 수량 |
| UNKNOWN 주문을 계속 찾지 못함 (조회 지연·오류 포함) | 기한이 지나도 `UNKNOWN`·전체 수량 예약·신규 진입 중단 유지, 알림 |
| **조회 3종이 모두 성공·빈 결과, 포지션 일치가 여러 번 지속된 뒤 늦은 `OPEN` 도착** | 그 전까지 예약과 진입 정지가 계속 유지되어 있었음. `OPEN` 도착 후 정상 추적 |
| UNKNOWN 진입 주문에 orderLinkId 취소 성공 | 이어 오는 상태로 종결(일부 체결 반영), 남은 예약 해제 |
| UNKNOWN 진입 주문 취소에 "주문 없음" 오류 | `UNKNOWN` 유지, 예약·정지 유지 |
| 사용자 수동 `NOT_FOUND` 확정 뒤 그 주문의 체결 도착 (M3 이후) | 실제 상태로 고치고 체결 반영, 알림 |
| `CANCELLED`/`FILLED` 통지가 execution보다 먼저 도착 → 다른 계약 진입 검사 → 지연 execution | 검사 시점에 미반영 체결이 노출에 포함됨 (02 2.1절) |
| 미반영 체결이 시간 안에 안 들어옴 | 체결 내역 조회로 반영, 그동안 해당 계약 신규 진입 중단 |
| 같은 체결이 WS와 REST로 두 번 도착 | execId 중복 제거, 장부 한 번만 반영 |
| 취소 경합으로 `Filled` 두 번 도착 | 두 번째는 무시, 상태 `FILLED` 유지 |
| WS 체결이 REST 접수 응답보다 먼저 도착 | `CREATED/SUBMITTED`에서 바로 `FILLED`로 이동, 장부 정상 |
| `CANCELLED` 확정 뒤 같은 주문의 체결 도착 | 체결 반영, 상태는 `CANCELLED` 유지 |
| 부분 체결 후 취소 | 체결 수량만 장부 반영, 부착 손절 수량 = 체결 수량 |
| **진입 체결 직후, 후속 처리 전 강제 종료** | 거래소에 부착 손절이 이미 있음(가상 거래소도 Partial 손절을 체결과 동시에 생성). 재시작 후 장부가 손절과 함께 복구됨 |
| 전략 청산 시작 후 장시간(수 시간) 미복구 | 그동안 남은 수량은 원래 손절로 보호됨. 재시작 시 청산 의도대로 이어서 처리 (01 1.4절) |
| 청산 시장가(IOC)가 일부만 체결 / 거절 | 남은 수량은 손절로 보호된 채 재시도. 횟수 초과 시 해당 계약 신규 진입 중단·알림, 손절 유지 |
| 청산 확정 전 손절 취소 시도 | 일어나지 않음: 전략 보유 0이 체결 내역으로 확인된 뒤에만 손절 취소 |
| 청산과 손절이 동시에 체결되어 다른 전략까지 감소 | 초과분을 S2 → S1 순서로 장부에서 빼고, 손절 수량을 보유량에 맞추고, 알림 |
| 청산 완료 후 손절 정리 | 전략별 손절 수량 = 보유량, 계약별 합계 = 순포지션 |
| 숏 최초·추가 진입, 숏 축소, 롱 → 숏 전환 | 03 4.1절 부호 계약 표의 기대값 |
| 앱에서 직접 청산(외부 감소) | 신규 진입 중단, S2 → S1 순서로 장부 감소, 초과 손절 취소, 알림 |
| 개인 WS 끊김 중 체결 | 재연결 후 03 4.3절 동기화로 장부 복구, 그동안 신규 진입 없음 |
| REST 스냅샷 직후 손절 체결 | 버퍼링된 WS 이벤트 재생으로 반영, 안정화 확인 후에만 진입 허용 |
| 손절 수량이 보유량보다 부족 | 보호 재등록 → 실패 시 시장가 축소, 알림 |
| 프로세스 강제 종료 후 재시작 | [03_SYSTEM_ARCHITECTURE.md](03_SYSTEM_ARCHITECTURE.md) 4.3절 동기화로 복구, 정지 상태 유지 |
| Oracle 접속 끊김 | 신규 진입 중단, Watchdog 알림. **보호 작업(손절 재등록·추적 손절·청산)은 로컬 저널에 기록 후 성공**. DB 복구 후 저널 반영, 중복 없음 |
| Oracle 끊김 중 보호 주문 응답 불명 → 재시작 | 저널 반영 → orderLinkId로 UNKNOWN 해소, 중복 보호 주문 없음 |
| Oracle 끊김 중 같은 손절을 두 번 amend하고 한 번 cancel → 복구 | 저널의 작업 3건이 모두 `(operation_id, phase)` 단위로 반영되고 최종 상태가 거래소와 같음 (03 5.4절) |
| 저널에 `requested`만 쓰고 종료 | 재시작 시 작업 종류별로 거래소에서 결과 확인 후 반영 |
| 두 계약 동시 진입이 계좌 한도를 넘음 | 위험 게이트에서 하나만 통과 (02 2.1절) |
| 같은 봉 재전달 / AI 축소 후 다음 봉 | 주문 1건, 보충 주문 없음 (03 4.1절) |
| 시세 공백 / 지연 봉 | 신규 진입 중단, 공백 보충 후 재개 |
| AI 시간 초과 / 형식 오류 / 비용 상한 | 신규 진입 안 함, 손절·청산 정상 |
| 일일 한도·낙폭·연속 손실 도달 | 정해진 정지 상태와 해제 방식. HALTED `/resume`은 02 5.1절 예시대로 |
| 텔레그램 미등록 사용자 명령 | 무시하고 기록 |
| 부분 진입 → 손절로 보유 0 → 남은 진입 취소 응답 유실 또는 늦은 체결 → 새 신호 | 기존 진입 주문 종결 확정 전에는 새 에피소드 없음, 늦은 체결은 손절로 보호된 채 청산 (D64) |
| 저널 `requested` 부분 기록 실패 → 긴급 전송 성공 → 응답 유실 → 재시작 | 거래소 대조로 그 주문을 받아들임, 보호·청산 주문 중복 없음 (D65) |
| 거래일 경계 (UTC 00:00) | 기준 평가액 갱신, 일일 정지 자동 해제 |

## 3. V1 백테스트 (D32: 구간 이동 검증)

- 데이터 (D70): Bybit 공개 API의 BTCUSDT·ETHUSDT 일봉·1시간봉과 펀딩비 **최근 3년**. 1분봉은 손절·청산 사건이 겹친 구간 재검증(3.1절)에 필요한 구간만 받는다. 저장은 백테스트용 SQLite(D29).
- 방식: 예시로 12개월 구간에서 값을 정하고 다음 3개월에서 확인한다. 이를 3개월씩 옮기며 반복한다. **확인 구간 결과만** 성과로 집계한다. 구간마다 계좌를 새로 시작하고, **그 구간 안의 마지막 봉에서** 모두 청산한다(D78, 상세는 M2-04). 어떤 실행도 자기 구간 밖 가격을 쓰지 않는다.
- 반영 비용: 거래 수수료(지정가/시장가 구분), 슬리피지 가정, 펀딩비, 거래소 수량 단위 내림.
- 미래 정보 차단: 마감된 봉만 사용하고, S2는 그 시점의 S1 상태만 본다. 지표 계산 코드는 실거래와 같은 코드를 쓴다.
- 체결은 아래 **가상 체결 규칙**(3.1절)을 따른다.
- 결과 기록: 거래 수, 승률, 평균 손익비, 최대 낙폭, 월별 손익, 연속 손실 최대값, 전략별·계약별 분해. 이 값들이 V2의 "예상 범위" 기준이 된다.
- 통과 조건: 확인 구간 합계가 비용 차감 후 손실이 아니고, 최대 낙폭이 낙폭 한도(L6)보다 작다. 구체 수치는 3.2절(D88).
- 재설계 뒤 판정 이력: D96(BTC·ETH 2021-06 ~ 2023-09) INDETERMINATE → D97 새 종목 4개에서 S1-B 단독 주 판정 + S1-B × S2-P 부 판정(M2-06). 데모 진입은 주 판정 PASS로 정한다.

### 3.1 가상 체결 규칙 (D49)

M1 가상 거래소, M2 백테스트, V2 그림자 장부(4장)가 **같은 규칙**을 쓴다. 그래야 세 곳의 결과가 같은 의미를 갖는다.

| 항목 | 규칙 |
|---|---|
| 신호 시점 | 봉 마감 시각 t의 종가로 신호를 만든다 |
| 최초 체결 가능 시점 | 다음 봉(t부터 시작하는 봉)의 시가. 신호를 만든 종가로는 체결하지 않는다 |
| 시장가 | 다음 봉 시가 ± 슬리피지(불리한 방향). 수수료는 테이커 |
| 지정가 | 이후 봉의 가격이 지정가를 **넘어서야** 체결(닿기만 하면 미체결). 체결가는 지정가, 수수료는 메이커. 유효 기간(다음 봉 마감 전)이 지나면 취소 |
| 손절(시장가 조건부) | 봉의 저가(롱)/고가(숏)가 trigger에 닿으면 발동. 체결가는 trigger ± 슬리피지. 시가가 이미 trigger를 넘어 열리면(갭) 시가 ± 슬리피지 |
| 진입 봉 안의 손절 | 진입한 봉에서 손절 가격에 닿았으면 손절된 것으로 본다(보수적) |
| 한 봉에 여러 사건 | 손절과 다른 유리한 사건(청산 신호 가격 등)이 같은 봉에서 모두 가능하면 **손절이 먼저**라고 본다 |
| 더 짧은 데이터 | 위 보수적 가정이 결과를 크게 바꾸는지 확인하려면, 해당 구간을 1분봉으로 다시 돌려 비교한다(선택, 결과 보고서에 표시) |
| 펀딩비 (D87) | **저장된 펀딩 기록의 시각**에 포지션을 들고 있으면 그 기록의 펀딩비율로 정산한다. 펀딩 주기는 계약마다 다르고 바뀔 수 있어서(Bybit instruments-info `fundingInterval`) 시각을 고정하지 않는다 |
| 수량 | 거래소 수량 단위로 내림. 최소 수량 미만이면 주문하지 않음 |
| 경계 시각 처리 순서 (D76) | 시각 T(1시간 경계)에서: ① T에 끝나는 봉 동안의 체결·손절 처리 → ② T가 펀딩 시각이면 그 시점 보유 포지션에 펀딩 정산 → ③ T가 UTC 00:00이면 거래일 기준값 저장(펀딩 후 지갑 잔고, D72) → 일일 정지 해제 → **곧바로 위험 상태 재검사**(L5·L6, 넘어온 미실현 손실로 다시 정지될 수 있음) → ④ 마감 봉으로 신호 계산: S1(일봉) → S2(1시간봉), 계약은 BTCUSDT → ETHUSDT → ⑤ 주문 생성 → ⑥ 주문은 T부터 시작하는 봉의 시가부터 체결 가능 |
| 데이터 완전성 (D77) | 실행 전에 두 계약 모두 [구간 시작 − 워밍업, 구간 끝) 범위의 일봉·1시간봉이 빠짐없이 있고, 구간 안 펀딩 기록이 끊기지 않았는지 검사한다(D87: 이웃한 두 기록의 간격, 그리고 구간 시작·끝과 가장 가까운 기록 사이 간격이 수집 시점 펀딩 주기보다 길면 빠진 것). 하나라도 빠지면 그 구간은 **무효**로 실행하지 않고, 성과 집계와 V1 판정에서 뺀다(보고서에 표시). 빈 봉을 지어내거나 펀딩을 0으로 채우지 않는다 |
| 같은 시각 두 계약 | BTCUSDT → ETHUSDT 순서로 위험 게이트에 넣는다(결정적 순서) |

### 3.3 D98 재설계 2 검증 (1~4 1단계 확정 2026-11-01, PR #37 Codex 통과 560c673 · 5 2단계 초안)

BTC·ETH(2021~2026)와 D97 4종목(2022~2026)은 모두 관측된 데이터다. D98은 **기초 자산 단위로 데이터를 나눠** 아직 보지 않은 데이터를 확보한다. 진행은 두 단계다(D98): **1단계**(1~4)는 가볍게 우위를 확인하고, **2단계**(5)는 1단계를 통과했을 때만 운영 구조를 바꾸고 판정한다.

#### 1. 계약 범위와 데이터 수명 (1단계)

- **대상 계약**: `category=linear`, `contractType=LinearPerpetual`, `quoteCoin=USDT`, `settleCoin=USDT`, `status ∈ {Trading, Closed}`(PreLaunch·Delivering 제외), **암호자산만**: `symbolType ∈ {"", "innovation"}`(`stock`·`ETF`·`commodity`·`forex` 제외, 그 밖의 값이 나오면 사람이 검토하기 전까지 도구가 멈춤). 공개 `instruments-info`를 페이지 끝까지 읽는다. 현재 메타데이터 목록이 과거 전체를 빠짐없이 담는지는 확인할 수 없으므로 한계로 적는다.
- **계약 수명**: 상장 = `launchTime`, 폐지 = `status=Closed`일 때 `deliveryTime`(무기한 폐지 시각, 0이면 폐지 시각 모름 → 그 계약은 제외하고 목록에 사유 기록). 계약 활성 구간 `[launch, delist)`.
- **정상 비활성과 누락의 구분**: 활성 구간 밖에는 데이터가 없는 것이 정상이다. 수집·검사는 활성 구간(워밍업 포함, 판정 범위로 자른 부분)에서만 연속성을 요구한다. 활성 구간 안의 1시간봉 공백은 누락이다.
- **폐지 처리(미래 정보 금지)**: 폐지 예정 시각을 미리 알고 진입을 피하지 않는다(진입 자격에 `deliveryTime`을 쓰지 않음). 손실 종목을 조용히 빼지 않는다.
  - **세 시각을 구분한다**: 폐지 시각 `D = deliveryTime`; 기대 마지막 완결 봉 시작 `L_e = floor_hour(D) − 1h`(끝 시각 ≤ D인 마지막 1시간봉, 정시가 아닌 폐지 시각의 미완결 봉은 제외); 실제 마지막 봉 시작 `L_a`와 그 끝 `E_a = L_a + 1h`(= 모형상 폐지 청산 시각).
  - **허용 꼬리**: `L_e − L_a ≤ 24h`이면 정상(폐지 전 거래 중단)이다. 이때 계약의 **데이터 끝은 `E_a`**이고, `[E_a, L_e + 1h)`의 봉은 누락으로 세지 않으며 유효성 검사 범위에서도 뺀다. 24시간보다 길면 데이터 끝은 `L_e + 1h`이고 `[E_a, L_e + 1h)`는 **누락**이다(4절 유효성 규칙 적용, 그 구간을 지나는 거래는 무효).
  - **폐지 청산 (허용 꼬리에서만, 하나의 예외 규칙)**: 보유 중 다음 처리에 필요한 봉의 시작이 `E_a` 이상이면(손절·시간 청산·H 청산이 모두 해당) 그 처리 대신 시각 `E_a`에 `P_x = close(L_a) × (1 − d × 0.02)`로 청산한다. 이 2%는 일반 슬리피지 등급을 **대체**한다(누적 아님). 테이커 수수료를 낸다. 꼬리 `[E_a, D)` 동안에는 손절·시간 청산 검사를 하지 않는다. 펀딩은 `t < τ ≤ E_a`인 정산만 반영하고, `τ = E_a` 정산의 평가가격은 `close(L_a)`다. `E_a`보다 뒤의 정산은 반영하지 않는다(한계로 보고).
- **누락 처리**: 고정 기간으로 빼지 않고, 4절의 **과거 입력 창**과 **미래 경로 창**에 필요한 데이터가 모두 있는지로 판단한다.
- **위험 등급(tier)·필터**: 1단계 신호 연구는 강제청산·노출 한도를 모델링하지 않으므로 쓰지 않는다. Closed 계약의 대체 모델 또는 INVALID_INPUT 처리는 2단계에서 정한다.
- **수집 계약 검증**: 판정용 풀 가격으로 가용성을 시험하지 않는다. 이미 관측한 Closed 계약(10000NFTUSDT·10000LADYSUSDT, 설계용 고정)과 합성 입력으로 검증한다.

#### 2. 기초 자산 키와 풀 분리 (1단계, 가격을 보기 전 한 번)

적용 순서는 고정이다: 필터(1) → 정규화 → 별칭 → 관측 예외 → 해시.
- **정규화**: `baseCoin`을 NFKC 정규화·대문자로 바꾼다. 10의 거듭제곱 배수(`10`~`10000000`, 예: `1000PEPE`, `SHIB1000`)를 **하나만** 뗀다: 앞(prefix)을 먼저 가장 긴 일치로 보고, 없으면 뒤(suffix)를 가장 긴 일치로 본다. 떼고 남은 이름이 비면 떼지 않는다. 숫자로 시작하는 실제 이름은 **예외 표**에 올려 떼지 않는다. 뗀 배수 값(없으면 1)을 계약별로 보존한다.
- **별칭 표**: 이름 변경으로 계약 이름이 바뀐 자산(예: MATIC→POL, RNDR→RENDER, FTM→S)을 한 키로 묶는다. 표는 메타데이터와 공지만으로 만들고, 표에 없는 경우는 다른 자산으로 본다(모호하면 묶지 않음).
- **관측 예외**: 정규화된 키 `BTC`·`ETH`·`SOL`·`ZEC`·`XRP`·`NEAR`·`NFT`·`LADYS`는 설계용 풀. 같은 자산의 다른 계약도 함께 설계용이 된다.
- **해시 규칙**: `sha256("D98-pool-v1|" + 키)`의 첫 바이트 짝수 → 설계용, 홀수 → 판정용.
- **제외 자산**: 스테이블·법정화폐·금 연동(M2-06 목록을 넓혀 상수로 고정: USDC, USDE, FDUSD, DAI, TUSD, PYUSD, USDD, EUR, PAXG, XAUT 등).
- **같은 자산의 계약이 동시에 여럿 활성**: 보존한 배수가 가장 작은 계약 하나만 쓴다(배수 없음 = 1). 같으면 `launchTime`이 이른 것, 그다음 심볼 이름순. 가격·수량은 거래소 원단위 그대로 쓰고, 배수는 자산 키를 만드는 데만 쓴다(값 환산 없음).
- 예외·별칭·제외 표는 풀 게시 전에 확정하고 digest에 넣는다. 게시 뒤에는 바꾸지 않는다(바꾸면 새 버전이고 판정용 풀의 미관측성을 다시 따져야 함).
- **출력**: 풀 목록 JSON(규칙 버전, 응답 정규화 사본, 예외·별칭·제외 표, `captured_at`, 계약별 수명·키·풀, digest)을 PR에 게시·병합한 뒤에만 설계용 풀 가격을 수집한다. 판정용 풀 가격은 2단계 사전 등록 전에 수집·조회하지 않는다.

#### 3. 신호 수식 (1단계)

시각은 UTC 밀리초, 1시간봉은 시작 시각으로 부르며 `[s, s+1h)`를 덮는다. 4시간 판단 시각을 t라 한다.
- **4시간봉**: `B_0 = [t−4h, t)`(신호봉), `B_i = [t−4h(i+1), t−4hi)`. 1시간봉 4개가 모두 있어야 만들어진다.
- **거래대금**: 분자 `A = Σ turnover(1h, 시작 ∈ [t−24h, t))`. 비교 묶음 `D_j = Σ turnover(1h, 시작 ∈ [t−24h(j+1), t−24hj))`, j = 1..30. 급증 배수 `V = A / median(D_1..D_30)`. 분모의 720개 1시간봉이 모두 있어야 하고(분자 24개 포함 744시간), 중간값이 0이면 자격 없음. 전체 입력 완결성은 4절 과거 입력 창으로 따로 검사한다.
- **유동성 자격·슬리피지 등급**: `mean(D_1..D_30)`로 정한다(D99: ≥ 200M 0.0005, 50M~200M 0.0010, 20M~50M 0.0015, 5M~20M 0.0025, 5M 미만 자격 없음; 경계값은 위쪽 등급). 등급은 신호 시각 t에 정해 그 포지션의 진입·모든 청산과 수량 계산에 같은 값으로 쓴다. S1-B 월별 상위 4개도 같은 30개 묶음(매월 첫 00:00 기준)을 쓴다.
- **상장 경과**: `t − launch ≥ 60일` 그리고 `F ≤ t − 60일`. F는 수집 시작 `max(launch, 2021-11-01T00:00Z)` 이후 처음 받은 1시간봉의 시작이다. 수집 시작이 첫 연구 시각보다 61일 앞서므로, 2021-11-01 이전에 상장해 그때부터 봉이 있는 계약은 연구 첫날부터 자격 증거가 있다. 그 뒤 상장 계약은 실제 첫 봉으로 검사한다.
- **돌파**: 롱 `close(B_0) > max(high(B_1..B_N))`, 숏 `close(B_0) < min(low(B_1..B_N))`(신호봉 제외, 엄격 비교).
- **EMA20·ATR14 (4시간)**: 기존 지표 계약처럼 마지막 10 × n개 4시간봉 창에서 매번 다시 계산한다(EMA는 창의 첫 20개 단순평균을 씨앗으로, 계수 2/21; ATR은 기존 Wilder 정의). 연구와 실시간이 같다.
- **펀딩**: 시각 ≤ t인 마지막 정산 τ₁과 그 앞 두 정산 τ₂, τ₃만 쓴다(시각이 정확히 t인 정산은 이미 반영된 것으로 보고 신호보다 먼저 처리). 다음 정산 시각은 쓰지 않는다.
  - 주기 `I = τ₁ − τ₂`. **`τ₁ − τ₂ = τ₂ − τ₃`이고 I ∈ {1, 2, 4, 8}시간**일 때만 유효하다(기록 하나가 빠져 2배 주기로 보이는 경우를 줄임). 아니면 자격 없음.
  - **신선도**: `t − τ₁ ≤ I`여야 한다(다음 정산이 이미 지났는데 기록이 없으면 자격 없음).
  - 8시간 환산율 = 율 × 8h / I. 불리함: 롱은 환산율 ≥ f, 숏은 환산율 ≤ −f.
  - 한계: 규칙적으로 빠진 기록(예: 1시간 주기에서 짝수 회차만 있음)은 이 검사로 찾을 수 없다. Trading 계약은 현재 `fundingInterval`과 최근 기록의 주기를 대조해 불일치를 보고서에 적는다(기술용).
- **BTC 추세 상태** (경로 의존 상태라 시작점을 고정한다): BTCUSDT 일봉, 채널 55.
  - 평가: 매 UTC 00:00에 막 닫힌 일봉 `[d−1일, d)`의 종가가 그 일봉을 뺀 직전 55개 일봉 최고가보다 엄격히 크면 `LONG`, 최저가보다 엄격히 작으면 `SHORT`, 아니면 이전 상태 유지.
  - **씨앗**: 2021-01-01T00:00Z에 `FLAT`으로 둔다. 첫 평가는 2021-01-02T00:00Z(일봉 `[2021-01-01, 2021-01-02)`), 채널에 쓰는 55개 일봉은 2020-11-07부터다. 그때부터 연구 끝까지 하루씩 순차 재생한다(연구 시작 2022-01-01의 상태는 이 재생으로만 정해짐).
  - 필요 데이터: BTCUSDT 일봉 `[2020-11-07, 연구 수집 끝)` 전부. 하나라도 빠지면 연구 전체를 진행하지 않는다(BTC는 이미 관측된 데이터이고 다시 받을 수 있음).
  - 일봉 경계 00:00에는 일봉 갱신을 먼저 하고 그다음 4시간 판단을 한다. BTC는 거래 풀과 별도의 **기준 입력**이며, 그 데이터도 data_hash에 들어간다.
  - 합성 회귀: 워밍업 초기에 돌파하고 연구 시작까지 돌파가 없는 경우, 연구 시작 상태가 그 방향이어야 한다.

#### 4. 신호 연구와 진행 기준 (1단계, 설계용 풀)

- **연구 방식**: 포트폴리오·슬롯·점유·위험 한도 없이, 유효한 신호마다 **독립된 단순 거래**(수량 1 기초 단위)를 만든다. 방향 d = +1(롱)/−1(숏), 슬리피지 등급 s(신호 시각에 정함, 3절), 테이커 수수료 c = 0.00055.
- **평가 단계와 분모 (데이터를 보기 전에 고정)**: 각 `(계약, t)`를 아래 순서로 분류하고, 각 단계 개수를 모두 보고한다.
  1. **평가 기회**: t가 4시간 격자이고 `t ∈ [2022-01-01, 2026-10-01)`, 풀이 설계용이고 그 시각에 쓰는 계약(2절 동률 규칙)이며 `launch ≤ t`이고 t가 그 계약의 데이터 끝보다 앞이다.
  2. **메타데이터 자격**: 제외 자산이 아니고 상장 경과(3절)를 만족한다. 불만족은 '자격 없음(메타)'.
  3. **과거 입력 완결성**: 1시간봉 `[t − 800h, t)`가 모두 있고(800h = EMA20의 10n 창 200개 4시간봉, 거래대금 744h·돌파 최대 336h·ATR 560h를 모두 덮음), 펀딩 τ₁·τ₂·τ₃가 있다. 하나라도 없으면 **'입력 부족'**(신호가 있었는지 알 수 없음). 이 단계까지는 조합과 무관하다.
  4. **데이터 자격**: 유동성 하한, 중간값 0, ATR = 0, 펀딩 주기 무효·신선도 실패는 '자격 없음(데이터)'.
  5. **신호 발생**: 조합별 급증·돌파·과열·펀딩 조건.
  6. **미래 경로 완결성**: 아래 미래 경로 창이 모두 있으면 **유효 신호**, 아니면 **'결과 무효'**.
  - **입력 부족률** = 입력 부족 ÷ 메타데이터 자격 통과 기회. **5%를 넘으면 연구 전체를 판정 불가**로 보고 2단계로 가지 않는다. 이 비율은 가격 결과를 보지 않고 계산할 수 있으므로, 신호 계산 전에 수집 감사 보고서에서 먼저 확인한다(재수집은 이 단계에서만 허용).
  - **결과 무효율** = 결과 무효 ÷ 발생 신호(조합별). **5%를 넘는 조합은 판정 불가**이며 진행 기준 1~3의 후보가 될 수 없다.
- **미래 경로 창**: 1시간봉 `[t, min(t + 169h, 데이터 끝))`이 모두 있어야 한다. 끝점 봉 `t + 168h`(H 청산 시가·같은 시각 펀딩 평가가격·7일 수익 관측)를 포함한다. 허용 꼬리로 데이터 끝이 `E_a`이면 꼬리 구간은 검사하지 않는다(1절). 펀딩은 `T_end = min(t + 168h, 데이터 끝)`에 대해, τ₁부터 `T_end` 이하의 정산들의 연속 간격이 모두 8시간 이하이고 `T_end − (T_end 이하 마지막 정산) ≤ 8h`여야 한다(양 끝 커버리지; 뒤쪽 정산이 통째로 없는 경우를 잡음).
- **진입**: 신호 다음 1시간봉(시작 t)의 시가 O로 `P_e = O × (1 + d·s)`. 초기 손절 `S₀ = close(B_0) − d·k·ATR_t`(신호 때 고정).
  - **갭**: 롱 `O ≤ S₀`(숏 `O ≥ S₀`)이면 진입과 동시에 같은 시가로 청산한다(`P_x = O × (1 − d·s)`). 평균에서 빼지 않는다.
- **R 분모**: 신호 때 정한 `R₀ = k × ATR_t`(> 0)를 모든 거래의 고정 분모로 쓴다. 실제 체결가 기준 위험은 쓰지 않는다(0·역전 문제가 없음).
- **순손익(가격 단위, 수량 1)**: `PnL = d·(P_x − P_e) − c·(P_e + P_x) − Σ funding`, `R = PnL / R₀`. 슬리피지는 체결가에만 반영하고 따로 빼지 않는다.
  - **펀딩**: 정산 시각 τ가 `t < τ ≤ 청산 시각`인 정산마다 `d × 율 × (시작 τ인 1시간봉 시가)`를 뺀다(롱은 양의 율에서 냄). 청산이 τ 정각이면 정산을 먼저 반영한다.
- **보유 중 1시간봉 처리** (진입봉 `[t, t+1h)`부터, 각 봉에서 이 순서):
  1. 그 봉 시작 시각의 펀딩 정산 반영. 단 진입봉의 시작 t에 있는 정산은 `t < τ` 조건에 따라 **반영하지 않는다**(신호 판단 전에 이미 처리된 정산).
  2. 그 봉 시작이 4시간 경계 u(> t)이면: (a) u가 00:00이면 BTC 추세 상태 갱신, (b) **시간 청산**: BTC 상태가 진입 방향과 다르거나 `FLAT`, 또는 보유 4시간봉 수가 H에 이르렀으면 그 봉 시가에 `P_x = O × (1 − d·s)`로 청산하고 끝. (c) 아니면 **추적 손절 갱신**: 진입 4시간봉 `[t, t+4h)`부터 u에 끝난 4시간봉까지의 종가 최고(롱)/최저(숏) E와 u에서 새로 계산한 ATR_u로 `S' = E − d·k·ATR_u`, 롱은 `S = max(S, S')`, 숏은 `S = min(S, S')`. 새 손절은 **이 봉부터** 효력이 있고, 과거 봉에 소급하지 않는다.
  3. **손절 판정**: 롱은 시가 ≤ S이면 시가에서(갭), 아니면 저가 ≤ S이면 S에서 청산(숏 대칭, 고가). 체결가는 각각 `가격 × (1 − d·s)`. 시간 청산(2b)과 갭이 같은 시가면 같은 가격이며 사유는 손절로 기록한다.
- **보유 수 H**: 진입 4시간봉 `[t, t+4h)`을 1번째로 센다. H = 42이면 42번째 4시간봉이 끝나는 `t + 168h`의 첫 1시간봉 시가에 청산한다(최대 보유 정확히 168시간).
- **기간과 끝 처리**: 신호는 `t ∈ [2022-01-01, 2026-10-01)`. 모든 거래가 H 안에 끝나고 7일 뒤 수익을 관측할 수 있도록 **수집은 2026-10-09T00:00Z(배타)까지 연장**한다(수집 시작은 2021-11-01T00:00Z: 800h 창과 60일 상장 증거를 모두 덮음). 미완료 거래로 빼는 경우는 없다. 폐지는 1절 규칙.
- **연도 귀속**: 신호 시각 t의 UTC 연도.
- **격자**: v ∈ {2, 3}, N ∈ {42, 84}, k ∈ {2, 3}의 8개 조합. e = 3, f = 0.0005(8시간 환산), H = 42는 고정. 수수료 c는 연구 시작 전에 정하고, 슬리피지 등급 수치는 D99로 확정했다. 모든 조합을 보고한다.
- **기술용 출력**: 신호 뒤 1·3·7일 수익 분포, 롱·숏, 연도별, 유동성 등급별, 2023-10 앞뒤, 무효·자격 없음 사유별 개수.
- **진행 기준 (데이터를 보기 전에 고정, 2단계로 가려면 모두 만족)**: 연구 전체가 판정 불가(입력 부족률 > 5%)가 아니어야 한다. 1~3은 판정 불가가 아닌 **같은 한 조합**이 함께 만족해야 하고, 그런 조합이 하나 이상 있으면 된다.
  1. 유효 신호 300개 이상, 평균 순 R ≥ 0.10.
  2. R 상위 `ceil(0.01 × 신호 수)`개(동률은 신호 시각, 심볼 이름순)를 빼도 평균 순 R > 0.
  3. 유효 신호 30개 이상인 해가 **3개 이상** 있고, 그중 과반에서 평균 순 R > 0.
  4. 8개 조합 중 4개 이상이 평균 순 R > 0(분모는 항상 8, 신호 0개·판정 불가 조합은 양수가 아닌 것으로 셈).
- 못 넘으면 S2-M을 버리고 판정용 풀은 손대지 않은 채 남긴다. 넘어도 이 결과는 설계 참고이지 판정이 아니다.

### 3.4 D101 분산 추세 신호 연구 (1단계, 설계용 풀, Claude 초안 2026-11-09)

D98 1단계 신호 연구(PR #50)는 **NO_GO**였다. 8개 조합 모두 평균 순 R < 0.10이었고, 상위 1% 거래를 빼면 모두 음수였다. 이익은 2024년 롱에 몰렸고 숏(평균 −0.04R)과 2022·2023·2025년은 손실이었다. S2 계열은 네 번 연속 우위가 없었다. 지금까지 유일하게 양의 순손익을 낸 규칙은 S1-B(D96 +388.8 USDT, D97 +7,878 USDT)다. 다만 둘 다 소수 종목이었고, D97에서는 거래 하나(+9,788)가 총손익보다 컸다.

D101은 **S1-B 규칙을 설계용 풀의 유동성 있는 모든 종목에 독립 적용**해서 우위가 소수 거래가 아니라 넓게 나오는지 확인한다. 구조는 3.3 4와 같은 신호 연구이고 결과는 진행 기준(go/no-go) 하나다. 3.3의 데이터 계약과 07c 도구를 그대로 다시 쓴다.

#### 1. 데이터 (새 수집 없음)

- D98 설계용 풀 수집 DB를 그대로 쓴다(풀 digest `8e5e2d0c…206fe`, 감사 `dace1ad6…7685`, data_hash `42acf4df…bc6c`). 판정용 풀 데이터는 수집·조회하지 않는다.
- DB는 **읽기 전용**으로 연다. D98 freeze 기록(등록 `f7388c07…`)은 바꾸지 않는다. 연구 도구는 D98과 같은 함수로 data_hash를 다시 계산해 일치를 확인하고, freeze 기록이 D98 등록 digest인지 확인한다(그 뒤 DB가 바뀌지 않았다는 증거). 둘 중 하나라도 다르면 계산 전에 거절한다.
- 계약 범위·데이터 수명·폐지 처리(3.3 1), 자산 키·동시 활성 계약 규칙(3.3 2), 유동성 자격·슬리피지 등급(D99, 3.3 3), 상장 경과 60일(3.3 3)은 그대로 쓴다.
- **일봉**: UTC 일 `[d, d+1일)`의 1시간봉 24개가 모두 있을 때만 만든다. 시가 = 첫 봉 시가, 고가·저가 = 최대·최소, 종가 = 마지막 봉 종가.

#### 2. 신호 (S1-B, 종목마다 독립)

- 판단 시각 t: 매 UTC 00:00. 신호일 `B_0 = [t−1일, t)`, `B_i = [t−(i+1)일, t−i일)`.
- **롱**: `close(B_0) > max(high(B_1..B_N))`. **숏**: `close(B_0) < min(low(B_1..B_N))`(신호일 제외, 엄격 비교).
- **계약마다 한 번에 거래 하나**: 그 계약에 보유 중인 거래가 있으면 새 신호를 만들지 않는다. 각 t에서 청산 처리(3절 2)를 먼저 하고, 그 결과 보유가 없을 때만 신호를 본다(반대 방향 돌파로 청산한 t에 같은 신호로 반대 방향 진입 = S1-B 뒤집기).
- **방향 모드**: `both`(롱·숏 모두) / `long`(숏 신호는 무시하고 진입하지 않음. 반대 방향 돌파 청산은 똑같이 적용).
- BTC 추세 상태 필터는 쓰지 않는다(S1-B는 계약별 추세). BTC 추세 상태(3.3 3 정의)는 진입 시점 값을 기술용으로만 기록한다.

#### 3. 평가 단계와 거래 규칙

- **평가 단계**(3.3 4와 같은 순서, 1~4는 조합과 무관하며 보유 여부와 관계없이 모든 `(계약, t)`를 센다)
  1. 평가 기회: t가 UTC 00:00이고 `t ∈ [2022-01-01, 2026-07-01)`, 설계용 풀에서 그 시각에 쓰는 계약, `launch ≤ t`, t가 데이터 끝보다 앞.
  2. 메타데이터 자격: 제외 자산이 아니고 상장 경과 60일.
  3. 과거 입력 완결성: 1시간봉 `[t − 56일, t)`(N 최대 55일 + 신호일, 거래대금 30일 묶음 744h를 덮음)가 모두 있어야 한다. 없으면 '입력 부족'. **입력 부족률 > 5%면 연구 전체 판정 불가.**
  4. 데이터 자격: 유동성 하한(D99, 5M 미만), `mean(D_1..D_30) = 0`.
  5. 신호 발생: 조합별, 그 계약에 보유가 없을 때만.
  6. 결과 완결성: 진입봉부터 **청산봉까지** 1시간봉이 모두 있고, 그 구간의 펀딩 정산 간격이 3.3 4 미래 경로 규칙(연속 간격 ≤ 8h, 청산 시각 앞 마지막 정산까지 ≤ 8h)을 만족하면 유효. 아니면 '결과 무효'(누락 시각에서 거래를 끝내고 결과에서 뺀다. 그 계약은 다음 t부터 다시 신호를 본다). **결과 무효율 > 5%인 조합은 판정 불가.**
- **진입**: t에 시작하는 1시간봉 시가 O로 `P_e = O × (1 + d·s)`. s는 t에서 정한 D99 등급(그 거래의 모든 체결에 같은 값).
- **초기 손절**: 롱 `S₀ = min(low(B_0..B_{M−1}))`, 숏 `S₀ = max(high(B_0..B_{M−1}))`(신호일 포함 최근 M일, D68 청산 채널). **R 분모** `R₀ = d·(close(B_0) − S₀)`. 엄격한 돌파라 구조상 `R₀ > 0`이지만, `R₀ ≤ 0`이 나오면 그 신호를 결과 무효(사유 `nonpositive_risk`)로 센다.
- **갭**: 롱 `O ≤ S₀`(숏 `O ≥ S₀`)이면 진입과 동시에 같은 시가로 청산한다(`P_x = O × (1 − d·s)`). 평균에서 빼지 않는다.
- **보유 중 1시간봉 처리**(진입봉부터, 각 봉에서 이 순서)
  1. 그 봉 시작 시각의 펀딩 정산 반영(`t < τ`, 진입봉 시작 t의 정산은 반영하지 않음). 3.3 4와 같은 식.
  2. 그 봉 시작이 UTC 00:00 u(> t)이면: (a) 막 닫힌 일봉으로 **반대 방향 돌파**(2절 식, 같은 N)면 그 봉 시가에 청산(사유 `reverse`). (b) `u − t ≥ H`이면 시가에 청산(사유 `H`). (c) 아니면 **추적 손절**: 롱 `S = max(S, min(low(u 기준 최근 M일봉)))`, 숏 `S = min(S, max(high(…)))`. 새 손절은 이 봉부터 효력이 있다.
  3. 손절 판정: 3.3 4와 같다(시가 갭이면 시가, 아니면 저가/고가 접촉 시 S, 체결가에 `(1 − d·s)`). 2(a)·2(b)와 갭이 같은 시가면 사유는 손절.
- **최대 보유** H = 90일(2160시간). 신호 끝을 2026-07-01로 두어 모든 거래가 데이터 끝(2026-10-09) 전에 끝난다. H 청산 비율을 보고한다(추세추종의 큰 이익을 자를 수 있음, 한계).
- **순손익·R·수수료·펀딩·폐지**: 3.3 4·3.3 1 그대로(`PnL = d·(P_x − P_e) − c·(P_e + P_x) − Σ funding`, `R = PnL / R₀`, c = 0.00055).
- **연도 귀속**: 신호 시각 t의 UTC 연도.

#### 4. 격자

`(N, M) ∈ {(20, 10), (55, 20)}`(D96·D97 S1-B 격자의 두 쌍) × 방향 모드 `{both, long}` = **4개 조합**. H, c, D99 등급은 고정이다. 모든 조합을 보고한다.

#### 5. 진행 기준 (데이터를 보기 전에 고정, 2단계로 가려면 모두 만족)

연구 전체가 판정 불가가 아니어야 한다. 1~4는 판정 불가가 아닌 **같은 한 조합**이 함께 만족해야 하고, 그런 조합이 하나 이상 있으면 된다.
1. 유효 거래 300개 이상, 평균 순 R ≥ 0.10.
2. R 상위 `ceil(0.01 × 거래 수)`개(동률은 신호 시각, 심볼 이름순)를 빼도 평균 순 R > 0.
3. 유효 거래 30개 이상인 해가 3개 이상이고, 그중 과반에서 평균 순 R > 0.
4. **진입일 묶음 평균 > 0**: 같은 t에 진입한 거래들의 평균 R을 하나의 값으로 보고, 그 값들의 평균이 > 0(같은 날 한꺼번에 나온 상관된 거래가 결과를 지배하지 않는지 확인).
5. 4개 조합 중 2개 이상이 평균 순 R > 0(분모는 항상 4, 판정 불가·거래 0개는 양수가 아닌 것으로 셈).

### 3.5 D102 펀딩 시장 중립 신호 연구 (1단계, 설계용 풀, Claude 초안 2026-11-10)

D101 1단계(PR #54)도 **NO_GO**였다. 네 조합 모두 평균 순 R < 0.10이었고, 상위 1% 제거 평균은 −0.07 ~ −0.18이었다. 비용을 빼기 전 R도 −0.02 ~ +0.03으로, 개별 종목의 방향 신호(돌파·눌림·모멘텀) 자체에 우위가 없었다. 이 결과들은 공통으로 시장 방향(2024년 상승장)에 결과가 좌우됐다.

D102는 방향을 맞히지 않는다. 같은 시각의 종목들을 **펀딩비 순으로 줄 세워**, 펀딩이 가장 높은 쪽(롱 과밀)은 숏, 가장 낮은 쪽(숏 과밀)은 롱으로 같은 금액씩 묶는다. 수익원은 두 가지로 가정한다. (1) 과밀한 쪽이 내는 펀딩을 받는 것, (2) 과밀이 풀리며 가격이 되돌아오는 것. 롱·숏 금액이 같으므로 시장 전체 방향의 영향은 줄어든다.

#### 1. 데이터 (새 수집 없음)

- 3.4 1과 같다. D98 설계용 풀 DB(data_hash `42acf4df…bc6c`)를 **읽기 전용**으로 쓰고, D98 freeze 기록(등록 `f7388c07…`)과 data_hash 재계산 일치를 계산 전에 확인한다. 판정용 풀은 계속 미관측이다.
- 계약 범위·수명·폐지(3.3 1), 자산 키·동시 활성 계약(3.3 2), 상장 경과 60일(3.3 3), D99 슬리피지 등급(3.3 3), 펀딩 반영식(3.3 4)을 그대로 쓴다.

#### 2. 신호와 바구니

- **재조정 시각** t: `2022-01-01T00:00Z`부터 H일 간격의 UTC 00:00. 마지막 t는 `t + H ≤ 2026-10-01`인 것까지다.
- **펀딩 점수** F: 정산 시각 τ가 `(t − L, t]`인 정산들의 8시간 환산율(율 × 8h / 주기) 단순 평균. 주기는 3.3 3처럼 연속한 두 정산의 간격이다.
  - 유효 조건: `(t − L, t]` 안에 정산이 하나 이상 있고, 창 직전 마지막 정산부터 창 안의 모든 연속 간격이 8시간 이하이며, `t − (t 이하 마지막 정산) ≤ 8h`. 주기는 {1, 2, 4, 8}시간이어야 한다. 아니면 데이터 자격 없음(`funding_coverage`).
- **자격 종목**(t마다): 평가 단계 1~4(아래 3절)를 통과한 계약.
- **유동성 하한**: `mean(D_1..D_30) ≥ 20M USDT`(D99 등급 경계 하나를 하한으로 씀). 숏을 거는 종목의 호가·상환 위험 때문에 D99 하한(5M)보다 높게 둔다. 슬리피지는 그 종목의 D99 등급(0.0005 / 0.0010 / 0.0015).
- **다리(leg) 구성**: 자격 종목 수 n이 **25 미만**이면 그 t는 '바구니 부족'으로 거래하지 않는다(현재 보유는 모두 청산). 아니면 `k = floor(0.2 × n)`.
  - 자격 종목 전체를 **한 줄로** 정렬한다. 키는 (F 내림차순, 심볼 문자열 오름차순). 이 순위의 **앞 k개가 숏 다리, 뒤 k개가 롱 다리**다. `2k ≤ 0.4n < n`이므로 두 다리는 겹치지 않는다(PR #55 P2-1; F가 모두 같아도 이름순 앞 k개 숏, 뒤 k개 롱).
  - 같은 자산 키의 계약은 3.3 2 동시 활성 규칙으로 하나만 쓴다.
- **목표 보유** `a_i`(부호 있음): 숏 다리 `a_i = −0.5 / k`, 롱 다리 `a_i = +0.5 / k`, 그 밖 0. 총 노출 `Σ|a_i| = 1`, 순노출 `Σ a_i = 0`. 아래 `w_i = |a_i|`, `d_i = sign(a_i)`. 기간 중 가격 변화에 따른 비중 이동은 무시하고 다음 t에 목표로 되돌린다(한계).

#### 3. 평가 단계 (3.3 4 순서, 조합과 무관)

단계는 **매일 UTC 00:00 격자의 모든 `(계약, t)`**에서 센다. 조합과 무관하며, 각 조합은 자기 재조정 시각에서 이 분류를 그대로 쓴다(같은 t의 자격 종목 집합은 네 조합이 같다).
1. 평가 기회: `t ∈ [2022-01-01, 2026-10-01)`, 설계용 풀에서 그 시각에 쓰는 계약, `launch ≤ t`, t가 데이터 끝보다 앞.
2. 메타데이터 자격: 제외 자산이 아니고 상장 경과 60일.
3. 과거 입력 완결성: 1시간봉 `[t − 31일, t)`(거래대금 30일 묶음 744h)가 모두 있고, 펀딩 정산이 `(t − 7일, t]`에 하나 이상 있다. 아니면 '입력 부족'. **입력 부족률(입력 부족 ÷ 메타데이터 자격) > 5%면 연구 전체 판정 불가.**
4. 데이터 자격: 아래 순서로 처음 걸리는 사유 하나만 기록한다. `mean(D_1..D_30) = 0`(`zero_mean`) → 유동성 20M 미만(`liquidity`) → 펀딩 점수 유효 조건을 **L = 1일과 7일 둘 다** 만족하지 못함(`funding_coverage`). 이 단계를 통과한 계약이 그 t의 자격 종목이다.

#### 4. 기간 손익 (조합마다, 겹치지 않는 기간 `[t, t + H)`)

기간은 조합의 재조정 시각 t마다 하나씩 생기고, 종류는 셋이다. 기간 끝 시각 `e = t + H`.

| 기간 종류 | 언제 | 기간 수익 `r_p` | 통계(평균·t·상위 1%·연도·복리·기준 5)에 포함 | 다음 t의 직전 보유 |
|---|---|---|---|---|
| **정상** | 바구니를 구성했고 두 다리 모두 결과 무효가 아닌 종목이 하나 이상 | 아래 식 | 포함 | 그 기간 목표 `a_i`(기간 중 폐지 청산한 종목은 0) |
| **현금** | 바구니 부족 t | `−(직전 보유 전체 청산 비용)`(보유가 없었으면 0) | **포함** | 0 |
| **무효** | 바구니는 구성했지만 한 다리의 모든 종목이 결과 무효 | 계산하지 않음 | 제외(개수만 셈) | 그 기간 목표 `a_i`(폐지 청산 종목은 0) |

- **가격**: `g_i = d_i × (O_i(e) / O_i(t) − 1)`. O는 그 시각에 시작하는 1시간봉 시가.
- **펀딩**: `t < τ ≤ e`인 정산마다 `f_i −= d_i × 율 × O_i(τ) / O_i(t)`(최초 1단위 명목 기준. 롱은 양의 율에서 냄, 3.3 4와 같은 방향).
- **펀딩 연속성**: t 이하 마지막 정산 → 기간 안 첫 정산, 기간 안 연속 정산 사이, 기간 안 마지막 정산 → 종료 시각(e 또는 폐지 시 `E_a`)의 간격이 모두 8시간 이하여야 한다. 아니면 그 종목·기간은 결과 무효(`funding_gap`).
- **폐지**: `E_a ≤ e`(같을 때 포함)이면 3.3 1 규칙대로 `E_a`에 청산한다.
  - 청산가 `P_x = close(L_a) × (1 − d_i × 0.02)`, `g_i = d_i × (P_x / O_i(t) − 1)`. 2%는 슬리피지를 **대체**하므로 g 안에 있다.
  - 펀딩은 `t < τ ≤ E_a`만 반영하고, `τ = E_a` 정산의 가격 비율은 `close(L_a) / O_i(t)`다. `E_a`보다 뒤의 정산은 반영하지 않는다.
  - 테이커 수수료 `w_i × c`를 그 기간 비용에 넣는다(슬리피지 없음). 이 종목의 직전 보유는 0이 되어 다음 t에 청산 비용을 다시 내지 않는다.
  - 청산 뒤 남은 기간은 현금(수익 0)이다.
- **결과 무효(종목)**: 필요한 1시간봉(진입 t의 시가, 종료 e의 시가, 각 τ의 시가)이 없거나 펀딩 연속성이 깨지면 그 종목·기간은 결과 무효다.
  - **재분배하지 않는다.** 그 종목의 기여 `w_i(g_i + f_i)`를 0으로 두고, 다른 종목 비중은 그대로다. 진입·청산 비용은 원래 목표대로 낸다(실제로 들고 있었다고 본다).
  - 결과 무효는 미래 데이터로만 알 수 있으므로, 이 처리는 실행 가능한 바구니가 아니라 연구 가정이다(한계).
- **거래 비용**: 각 재조정 시각 t에서 `Σ_i |a_i(t) − a_i(직전)| × (c + s_i)`(c = 0.00055).
  - `s_i`는 t에서 그 종목이 자격 종목이면 t의 D99 등급이다. 자격이 없으면(유동성 미달·입력 부족·데이터 끝 등) **그 종목이 마지막으로 자격이었던 t의 등급**을 쓴다.
  - t의 재조정 비용은 **t에서 시작하는 기간**에 귀속한다(현금 기간 포함).
  - 마지막 재조정 시각의 기간 끝 e에는 전체 청산 비용 `Σ|a_i| × (c + s_i)`를 그 마지막 기간에 넣는다.
- **기간 순수익(정상)**: `r_p = Σ_i w_i (g_i + f_i) − 비용`. 펀딩 몫 `Σ w_i f_i`, 가격 몫 `Σ w_i g_i`, 롱·숏 다리별 수익을 따로 기록한다.

#### 5. 격자

`L ∈ {1일, 7일}`(펀딩 점수 창) × `H ∈ {3일, 7일}`(보유·재조정 간격) = **4개 조합**. 유동성 하한 20M, 다리 비율 0.2, 최소 자격 25, 비용은 고정이다.

#### 6. 진행 기준 (데이터를 보기 전에 고정, 2단계로 가려면 모두 만족)

연구 전체가 판정 불가가 아니어야 한다. **조합 판정 불가**: 결과 무효 종목·기간이 정상·무효 기간의 전체 보유 종목·기간의 5% 초과, 또는 (현금 + 무효 기간)이 전체 기간의 5% 초과.

아래에서 **유효 기간** = 정상 + 현금 기간이다(4절 표). n = 유효 기간 수, 시계열은 시각순.
1~5는 판정 불가가 아닌 **같은 한 조합**이 함께 만족해야 하고, 그런 조합이 하나 이상 있으면 된다.
1. `n ≥ 100`, 평균 > 0, `t = 평균 / (s / √n) ≥ 2.0`(s는 표본 표준편차, 분모 n − 1).
   - `s = 0`이면 t는 정의하지 않고(출력 `null`), 평균 > 0이면 이 기준은 통과로 본다(모든 기간이 같은 양수인 퇴화 경우). `n < 2`면 실패.
2. `r_p` 상위 `ceil(0.01 n)`개(동률은 시각 오름차순으로 앞의 것부터 뺌)를 빼고 남은 기간의 평균 > 0.
3. 유효 기간 20개 이상인 해(기간 시작 t의 UTC 연도)가 3개 이상이고, 그중 과반(엄격)에서 `r_p` 합 > 0.
4. 복리 자산 `E_0 = 1`, `E_p = E_{p−1} × (1 + r_p)`. 최대 낙폭 `max_p (1 − E_p / max_{q ≤ p} E_q)`(최고점에 `E_0` 포함) < 25%.
   - 어떤 `r_p ≤ −1`이면 그 시점에 **파산**: `E = 0`으로 두고 이후 곱하지 않으며, 낙폭은 100%라 기준 4 실패. 보고서에 파산 시각을 적는다.
5. **종목 집중**: 정상 기간의 결과 무효가 아닌 모든 종목·기간의 기여 `x = w_i(g_i + f_i)`(폐지 청산 포함)를 모아 N이라 한다. 기여가 큰 순(동률은 t 오름차순, 그다음 심볼 문자열 오름차순)으로 상위 `ceil(0.01 N)`개 집합 S를 정한다.
   - `r'_p = r_p − Σ_{(i,p) ∈ S} x`로 고치고, 비용·비중·현금 기간은 그대로 두며 재분배하지 않는다.
   - 분모는 그대로 n이고, `mean(r') > 0`이어야 한다.
6. 4개 조합 중 2개 이상이 유효 기간 평균 > 0(분모는 항상 4, 판정 불가는 양수가 아닌 것으로 셈).

#### 7. 기술용 출력 (판정에 쓰지 않음)

- 설계용 풀은 D98·D101에서 이미 다른 신호의 결과를 봤다. 펀딩 순위 수익은 아직 계산하지 않았다.
- 비중 이동 무시·목표 비중 재조정은 실제 체결보다 회전율을 약간 적게 본다. 숏 차입·상환 제약은 무기한 선물이라 없지만, 강제청산·위험 등급·ADL은 모델링하지 않는다(손절 없음, 총 노출 1배).
- 기간 수익을 독립으로 보고 t 통계량을 계산한다(자기상관 무시).
- 결과 무효 종목은 기여를 0으로 두고 재분배하지 않는다. 결과 무효는 미래 데이터로만 알 수 있어 실행 가능한 처리는 아니다. 한 다리 전체가 무효인 기간은 통계에서 빠지므로 그 기간의 비용도 집계에서 빠진다(개수는 보고, 5% 상한).
- 펀딩 점수는 정산 기록만 쓰고 예측 펀딩(다음 정산 예정치)은 쓰지 않는다. 실시간 운용과 차이가 있다.
- 기간 시작가를 그 시각 1시간봉 시가로 보며, 모든 종목이 같은 시각에 체결된다고 가정한다.

### 4.1 AI 효과 비교: 독립 그림자 장부 (D50)

실제 계좌에 거래별 가상 결과를 붙이는 방식으로는 비교가 안 된다. AI가 진입을 한 번 막으면 이후 포지션, 평가액, 한도, 다음 진입 후보가 모두 달라지기 때문이다. 그래서 같은 시장 이벤트로 **완전히 독립된 가상 계좌 두 개**를 함께 돌린다.

| 장부 | AI | 체결 |
|---|---|---|
| `shadow_ai` | signal_id별 공유 AI 점수(`ai_scores`)를 사용 | 3.1절 가상 체결 규칙 |
| `shadow_noai` | `disabled` (전부 통과, 계수 1.0). AI 호출 없음 | 3.1절 가상 체결 규칙 |

- 두 장부는 같은 시작 평가액과 같은 설정으로 시작하고, 각자 포지션·예약·수수료·펀딩비·한도·정지 상태를 따로 가진다. 전략·위험 코드는 실제 계좌와 같은 코드를 쓴다.
- **AI 점수 (D56)**: AI 입력은 시장 정보만 쓰므로(01 2.3절) 같은 신호의 점수는 계좌와 무관하다. 점수는 **시장 신호(signal_id)마다 한 번** 만들어 `ai_scores`에 저장하고, 실제 계좌와 `shadow_ai`가 같은 값을 쓴다. 실제 계좌가 진입하지 않는 신호(정지 중, 이미 보유 등)도 점수를 만든다. 비용은 실제 계좌 단독 운영과 같다(시장 신호 수만큼).
- 어떤 신호의 점수가 없으면(AI 실패·시간 초과·비용 상한) `shadow_ai`도 실제 계좌와 같이 그 신호로 진입하지 않는다. `shadow_noai`는 점수와 관계없이 진행한다.
- 그림자 장부는 실제 계좌의 정지 상태와 무관하게 자기 상태로 계속 평가한다. M1 테스트로 고정: 실제 계좌만 HALTED인 동안에도 두 그림자 장부가 신호를 평가하고 진입한다.
- **AI 효과 판정은 `shadow_ai`와 `shadow_noai`를 비교한다.** 둘 다 같은 가상 체결 규칙을 쓰므로, 실제 체결이 없는 거절 건도 공정하게 비교된다.
- 실제 계좌와 `shadow_ai`의 차이는 **가상 체결 규칙의 정확도**를 보는 데 쓴다("백테스트와 비슷한 결과" 조건의 체결가·수수료 차이).
- 비교 지표: 수수료·펀딩비 차감 후 순손익, 최대 낙폭, 거래 수, 거래당 평균 손익(R 배수), 전략별 분해.
- D34 "AI 효과가 손해가 아님" 판정: `shadow_ai`의 순손익 ≥ `shadow_noai`의 순손익 **그리고** `shadow_ai`의 최대 낙폭 ≤ `shadow_noai`의 최대 낙폭 × (1 + 허용 폭). 허용 폭은 V2 시작 전에 이 문서에 적는다.
